# خطة استخدام منحة 10,000 دولار لتطوير MVP لمنصة SENSE

## 1. القرار التنفيذي

لا تُستخدم المنحة لبناء «منصة وطنية كاملة» من اليوم الأول، ولا لتمويل متجر واسع أو نظام حجوزات ودفع أو NFC إنتاجي. تُستخدم لبناء واختبار **MVP سياحي وتجاري صغير قابل للقياس** يبدأ من العيزرية، ويثبت أن الرحلة التالية ممكنة:

> قصة موثوقة → وجهة واضحة → مسار قابل للفهم → تجربة أو مزود محلي → منتج محلي → ملاحظة وقياس.

إذا نجحت التجربة، يصبح التوسع إلى بيت لحم وبيت ساحور وبيرزيت وسلفيت قرارًا مبنيًا على دليل، لا مجرد توسع بصري في الصفحات.

## 2. نطاق MVP المقترح

### ما سيحتوي عليه الإصدار الأول

- واجهة عربية RTL متجاوبة مع الهاتف.
- صفحة رئيسية تشرح SENSE خلال ثوانٍ.
- صفحة وجهة تجريبية للعيزرية.
- مسار واحد قابل للمراجعة، يضم 5–7 محطات كحد أقصى.
- 5–8 بطاقات قصص أو معالم، مع حالة التحقق والمصدر وتاريخ المراجعة.
- 3–5 مزودين أو حرفيين بعد موافقة واضحة منهم.
- 5–10 منتجات أو نماذج منتجات دون ادعاء توفر أو سعر قبل التأكيد.
- نموذج «أرغب بالمشاركة/الاستفسار» بدل الدفع والحجز الآلي.
- سجل مصادر وحقوق وموافقات.
- معلومات وصول عملية عندما تتوفر ميدانيًا، مع وسم ما لم يُتحقق منه.
- لوحة قياس بسيطة للزيارات، النقرات، طلبات التواصل، التصحيحات، وملاحظات المستخدمين.

### ما لن يدخل في MVP

- بوابة دفع أو تسويات مالية.
- توصيل فعلي أو إدارة مخزون آلية.
- حجز مؤكد أو بيع فوري.
- نظام NFC إنتاجي أو مفاتيح حقيقية.
- تطبيق هاتف أصلي منفصل.
- توسع وطني قبل نجاح الاختبار المحلي.
- ادعاءات عن أعداد مستخدمين أو إيرادات غير موثقة.

- مراجعة الاسم والوصف والمعلومات القانونية للمنصة.

**بوابة القرار:** لا يبدأ التطوير الموسع قبل اعتماد مسار واحد و5–8 عناصر قابلة للتحقق.

### الشهر الثاني: البحث والبيانات — 1,600$

## 5. مؤشرات النجاح المقترحة

### مخرجات يمكن الالتزام بها

- مسار واحد منشور ومراجع.
- 5–8 بطاقات وجهة/قصة ذات مصادر وحالات واضحة.
- 3–5 مزودين بموافقات موثقة.
- 5–10 بطاقات منتجات أو نماذج منتجات.
- 10–15 اختبار مستخدم موثق.
- 3 جلسات مراجعة على الأقل مع مزودين أو أصحاب معرفة محلية.
- نسبة 100% من الصور والقصص المنشورة ذات حالة حقوق معروفة.
- تقرير ختامي يوضح ما تحقق وما لم يتحقق.

### مؤشرات أثر أولية، لا وعود مسبقة

- نسبة المستخدمين الذين وجدوا معلومة الوجهة خلال دقيقتين.
- نسبة المستخدمين الذين فهموا الخطوة التالية.
- عدد طلبات التواصل أو الإحالات للمزودين.
- عدد التصحيحات أو التحديثات التي وصلت من المجتمع.
- نسبة البطاقات التي تحتوي معلومات وصول عملية.
- رضا المزودين عن طريقة عرض قصصهم ومنتجاتهم.
- نسبة العناصر التي بقيت محدثة بعد 30 يومًا.

## 6. آلية الصرف والحوكمة

- الصرف على دفعات مرتبطة بمخرجات، وليس دفعة واحدة.
- لا تُدفع تكلفة محتوى أو تصوير دون موافقة حقوق واضحة.
- يحفظ لكل مصروف: المورد، الغرض، التاريخ، الإيصال، والنتيجة.
- لا تُستخدم أموال المنحة لشراء إنتاج إعلامي لا يدخل في MVP أو لا يمكن إعادة استخدامه.
- لا تُرفع كلمات مرور أو مفاتيح دفع أو مفاتيح NFC إلى GitHub.
- تظل WordPress طبقة نشر، ويظل GitHub مصدر الكود والوثائق وسجل التغيير.
- كل شريك أو مزود يملك حق مراجعة ما ينسب إليه قبل النشر.
