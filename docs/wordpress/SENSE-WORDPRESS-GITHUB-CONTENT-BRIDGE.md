# جسر WordPress → GitHub Routes

## الغرض

يشرح هذا الملف كيف تنتقل قصة SENSE من WordPress إلى بطاقة مسار قابلة للمراجعة في GitHub Pages، دون تحويل القصة الصحفية إلى إعلان أو تحويل بطاقة المسار إلى شهادة اعتماد.

## قاعدة الفصل

- **WordPress:** يشرح لماذا يهم المكان، ويعرض القصة والسياق والأسئلة الإنسانية.
- **GitHub Routes:** يعرض حالة المسار، المدة، نوع التجربة، مستوى الصعوبة، المصدر، الوصول، الحجز، والدليل التالي المطلوب.
- **القرار المحلي:** يحدد ما إذا كان المسار قابلًا للتشغيل أو ما زال يحتاج مالكًا أو إذنًا أو فحصًا.

## المسار التحريري

```text
ملاحظة أو قصة
    ↓
مراجعة المصدر والخصوصية والموافقة
    ↓
مسودة WordPress
    ↓
معرّف مصدر في routes.json
    ↓
بطاقة مسار بحالة واضحة
    ↓
اختبار قراءة أو فحص ميداني
    ↓
تحديث الحالة أو إبقاء المسار موقوفًا
```

## الربط الحالي

| طبقة | الملف أو الرابط | الوظيفة | الحالة الحالية |
|---|---|---|---|
| القصة الرئيسية | `docs/wordpress/SENSE-AL-EIZARIYA-FEATURE-NOT-A-STOP.md` | تقرير عن العيزرية بوصفها مكانًا حيًا | مسودة تحريرية جاهزة للمراجعة |
| قصة بطاقات الثقة | `docs/wordpress/SENSE-AL-EIZARIYA-TRUST-CARDS-STORY.md` | شرح قراءة حالة المسار | مسودة تحريرية جاهزة للمراجعة |
| عقد البيانات | `tourism/data/routes.json` | المصدر العام للبطاقات | `schemaVersion 1.1.0` |
| الواجهة | `tourism/index.html` و`tourism/app.js` | العرض والتصفية وخطة اليوم | منشورة / قابلة للاختبار |
| WordPress المنشور | `https://sense133.wordpress.com/` | قناة القصة العامة | لا يعني أن كل مسار تشغيلي |

## حقول يجب ألا تتعارض

عند تحديث قصة أو بطاقة، يجب مراجعة الحقول التالية معًا:

| WordPress | GitHub Routes | قاعدة المراجعة |
|---|---|---|
| المكان | `location` | لا تُذكر نقطة دقيقة إذا كانت خاصة أو غير متحققة |
| المصدر | `confidence.basis` | المصدر يثبت ما يقوله فقط، ولا يثبت تلقائيًا الوصول أو الحجز |
| حالة التحقق | `contentStatus` | قصة تحريرية ليست خدمة تشغيلية |
| الوصول والخصوصية | `access` | لا دخول أو تصوير دون إذن واضح |
| الدعوة إلى الإجراء | `booking` و`publicAction` | لا تستخدم «احجز الآن» إذا لم يوجد مضيف وسعر وسعة وسياسة |
| تاريخ المراجعة | `lastReviewed` و`verifiedAt` | كل تغيير جوهري يحتاج تاريخًا جديدًا |

## قواعد صياغة WordPress

1. ابدأ بسؤال أو مشهد، لا بقائمة مزايا.
2. افصل الوقائع المدعومة من المصدر عن الرواية المحلية وعن الفكرة المقترحة.
3. لا تجعل زر GitHub بديلًا عن زيارة أو حجز.
4. اذكر ما لا نعرفه عندما يؤثر على سلامة الزائر أو خصوصية السكان.
5. اجعل دعوة الإجراء: «اقرأ البطاقة وتحقق من حالتها»، لا «احجز فورًا».
6. لا تنسب شراكة أو تمويلًا أو اعتمادًا إلى بلدية أو UrbanUp أو تكنوبارك دون وثيقة مستقلة.

## اختبار الاتساق قبل النشر

- هل يحمل الرابط في المقال إلى الصفحة الصحيحة؟
- هل يوجد مصدر لكل ادعاء مركزي؟
- هل تطابق مدة المسار ونوعه ما يظهر في البطاقة؟
- هل حالة الوصول أكثر تحفظًا من أو مساوية لما تقوله القصة؟
- هل حالة الحجز تمنع الوعد إذا لم يوجد مضيف مؤكد؟
- هل توجد موافقة عند ذكر شخص أو بيت أو صورة قابلة للتعرف؟
- هل يحتاج المقال أو البطاقة إلى تاريخ مراجعة جديد؟

## الحالة الحالية

SENSE Routes تربط القصة بالبطاقة، لكنها لا تثبت بعد أثرًا سياحيًا أو اقتصاديًا أو بلديًا. الخطوة التالية ليست إضافة حجوزات وهمية، بل اختبار بطاقة أو بطاقتين مع قارئ ومراجع محلي، ثم تسجيل ما فهمه وما اعترض عليه وما يحتاج إلى دليل.
