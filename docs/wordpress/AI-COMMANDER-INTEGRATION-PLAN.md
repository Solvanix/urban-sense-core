# خطة ربط AI Commander بمحتوى SENSE وWordPress

## القرار

نستخدم مستودع `WordPress-AI-Commander` كمرجع تقني للمساعد الصوتي، ونبني تكامل المحتوى الخاص بـ SENSE داخل `urban-sense-core` أولًا على مستوى المواصفات والعقود. لا ننسخ المستودع كاملًا إلى النواة، ولا نخلط قواعد WordPress ببيانات Urban‑Sense الخاصة.

## حدود الإصدار الأول

الإصدار الأول ينجز دورة واحدة آمنة: استقبال نص أو صوت، إنشاء مسودة قصة أو خبر، رفع صورة، إنشاء نص بديل، إرجاع ملخص صوتي، ثم حفظ المادة في WordPress دون نشر تلقائي. لا يشمل الحذف، أو العمليات الجماعية، أو تعديل إعدادات الموقع، أو الدفع، أو الحجز.

## المكوّنات

| المكوّن | المسؤولية |
|---|---|
| واجهة AI Commander/PWA | استقبال الصوت أو النص وإظهار حالة المهمة |
| خدمة التفريغ | تحويل التسجيل إلى نص مع حفظ المصدر |
| محرر المحتوى | اختيار نوع المادة وبناء العنوان والمقدمة والمتن |
| طبقة التحقق | كشف الادعاءات بلا مصدر وتسجيل حالة التحقق |
| طبقة الإتاحة | النص البديل، بنية العناوين، وصف الوسائط، والملخص الصوتي |
| WordPress REST API | إنشاء المسودة ورفع الوسائط وربطها بالمقال |
| urban-sense-core | حفظ العقود والحدود والقرارات والوثائق العامة |

## تدفق الاستخدام

يبدأ المستخدم بأمر مثل: «حوّل هذا التسجيل إلى قصة ميدانية». يسأل المساعد عن المكان والتاريخ والموافقة إن كانت ناقصة، ثم ينتج بطاقة مادة ومسودة. يعرض للمستخدم العنوان والملخص والوسائط والمعلومات الناقصة صوتيًا ونصيًا. عند الموافقة على الحفظ، ينشئ مسودة WordPress ويربط الصورة والنص البديل والمصادر. لا يتم النشر إلا بأمر مستقل وواضح.

## عقد المسودة

يجب أن تحمل كل مسودة البيانات التالية على الأقل: `content_type`, `title`, `subtitle`, `summary`, `body`, `place`, `event_date`, `author`, `verification_status`, `sources`, `consent_status`, `media`, `alt_text`, `build_status`, `last_reviewed_at`, و`source_record`.

تُرسل الحقول الخاصة بـ SENSE إلى WordPress عبر حقول مخصصة أو نوع منشور مخصص بعد التأكد من وجود endpoint رسمي. لا يجوز إسقاط البيانات غير المدعومة بصمت؛ يعاد الخطأ للمستخدم بلغة مفهومة ويُحفظ المحتوى كمسودة محلية أو نص قابل للنسخ.

## حالات الفشل

إذا تعذر التفريغ، يحفظ المساعد التسجيل ويطلب نصًا بديلًا. إذا غاب المصدر، يضع المادة في حالة «قيد التحقق» ولا يقترح النشر. إذا فشل رفع الصورة، يبقى المقال مسودة مع تنبيه واضح. إذا انقطع الاتصال، لا يعيد إنشاء المقال تلقائيًا قبل التحقق من عدم وجود نسخة سابقة.

## الصلاحيات والأمان

يُستخدم حساب WordPress منفصل للمساعد بأقل صلاحية لازمة، مع كلمة مرور تطبيق مستقلة وقابلة للإلغاء. لا تُخزن كلمة المرور الأساسية أو رموز المصادقة في GitHub أو ملفات المحتوى. يجب تسجيل العمليات المهمة، وتكون النتيجة الافتراضية للمقال `draft`.

## الوصول

تُختبر الواجهة مع قارئ شاشة حقيقي وبالعربية، وتدعم لوحة المفاتيح والعناوين المنطقية والرسائل النصية الواضحة. لا نفترض أن الصوت وحده كافٍ؛ فالمستخدم قد يحتاج إلى نص، أو لوحة مفاتيح، أو ملف قابل للتنزيل. لا يقدم المساعد نفسه كبديل لقارئ الشاشة.

## الاختبار المرحلي

يُقبل النموذج الأولي عندما يستطيع إنشاء ثلاث مسودات مختلفة: قصة ميدانية، خبر محلي، وملف مكان. يجب أن يحتفظ بالمصدر، يرفض الادعاء بلا دليل، يرفع صورة بوصف بديل، ويعيد رابط المسودة. ويجب أن يتوقف قبل النشر أو الحذف ويطلب تأكيدًا واضحًا.

## ما يحتاجه التنفيذ الفعلي

يتطلب الربط النهائي رابط WordPress، وبيئة تجريبية أو نسخة احتياطية، وحسابًا منفصلًا بصلاحية مناسبة، وتحديد ما إذا كانت أنواع المنشورات المخصصة ستنفذ عبر إضافة مستقلة أو عبر إعداد WordPress الحالي. لا تستخدم بيانات الدخول في GitHub أو في محادثة عامة.

## العلاقة مع Stunning

يمكن تقييم Stunning لاحقًا كواجهة أو بيئة لبناء Agent، لكن لا تعتمد الخطة عليها. مصدر الحقيقة هو عقد المحتوى، وWordPress هو وجهة المسودة، وAI Commander هو نقطة الانطلاق التقنية للمساعد الصوتي.
