# مطابقة Problem Statement Canvas مع أول Vertical Slice

## الخلاصة التنفيذية

يصف Canvas مشكلة واسعة: **تشتت المعلومات والمسارات والمسؤوليات بين معالم العيزرية وطرقها وفعالياتها ومزوديها واحتياجات الزوار**. أما Vertical Slice الأولى المبنية في المستودع فتثبت جزءًا أضيقًا وقابلًا لإعادة الإنتاج: **دورة البلاغ الحضري من الاستقبال إلى الإقرار والإحالة والإغلاق والتقييم**.

لذلك لا ينبغي تقديم الشريحة الحالية بوصفها تحققًا كاملًا من مشكلة السياحة أو دليلًا على أثر اقتصادي. هي تثبت أن SENSE يستطيع أخذ سجلات ذات طوابع زمنية، تخزينها في SQLite، حساب مؤشرات مشتقة، وإظهار نتيجة قابلة للتتبع في Visualizer.

## ما يقوله Canvas

| عنصر Canvas | المضمون | حالة التحقق الحالية |
|---|---|---|
| المشكلة | الأصول السياحية غير متصلة في نظام واحد واضح يربط المعالم والطرق والفعاليات والمزودين والمحتوى واحتياجات الزوار | فرضية منتج، لم تُقَس بعد في البيانات الحالية |
| السياق | يحدث الاضطراب قبل وأثناء رحلة الزائر: المرور دون توقف، صعوبة العثور على معلومة موثوقة، وعدم معرفة الخطوة التالية | غير ممثل في بيانات البلاغات الحالية |
| البدائل الحالية | الخرائط العامة، وسائل التواصل، الاتصال المباشر، الزيارات، صفحات متفرقة، والكلمة المنقولة | موصوفة سياقيًا فقط |
| المستخدمون | الزوار، العائلات، الطلبة، ذوو الإعاقة، التجار، المرشدون، الحرفيون، المبدعون، والبلدية | غير ممثلين كأحداث رحلة في الشريحة الأولى |
| الأثر العاطفي | ارتباك وانفصال للزائر، إحباط وعدم ظهور للمزود، ضغط وتشتت للبلدية | غير قابل للقياس من جدول البلاغات وحده |
| الأثر القابل للقياس | التوقف، مدة المكوث، زمن المعلومة الموثوقة، الوصول الشامل، التحويل من المحتوى إلى زيارة، الحجوزات، المزودون، إغلاق البلاغ، وقيمة التجارة المحلية | غُطي فقط جزء إغلاق البلاغ، وببيانات اصطناعية |

## ما تثبته Vertical Slice الأولى

المسار الحالي هو:

```text
seed/reports.csv
→ SQLite reports
→ طوابع زمنية
→ مؤشرات زمنية ومقارنات مناطق
→ تنبيهات
→ dashboard.json
→ Visualizer
```

وتحسب الشريحة فعليًا:

- الوسيط حتى إقرار البلاغ.
- الوسيط حتى الإحالة.
- الوسيط حتى الإغلاق.
- معدل إعادة الفتح.
- متوسط التقييم.
- الاتجاه اليومي.
- مقارنة المناطق.
- توزيع الفئات.

هذه المؤشرات تلامس بند Canvas الخاص بـ **case closure time**، لكنها لا تقيس وحدها اكتشاف الزائر أو التوقف أو النشاط الاقتصادي.

## الفجوة المطلوبة بعد الشريحة الأولى

لتحويل Canvas إلى نظام قابل للاختبار، نحتاج إلى شريحة ثانية لرحلة الزائر:

```text
مشاهدة محتوى
→ فتح صفحة مكان
→ طلب معلومة موثوقة
→ الضغط على اذهب للمكان
→ فتح مسار
→ زيارة أو check-in مجهّل
→ تقييم الوصول والتجربة
→ تفاعل مع مزود محلي
```

وتحتاج هذه الشريحة إلى أحداث مجهّلة لا بيانات شخصية، مثل:

| الحدث | الحقول الدنيا | المؤشر الناتج |
|---|---|---|
| مشاهدة محتوى | `event_id`, `content_id`, `timestamp`, `source_channel` | الوصول للمحتوى |
| فتح مكان | `content_id`, `place_id`, `timestamp` | انتقال المحتوى إلى المكان |
| طلب معلومة | `place_id`, `information_type`, `verified`, `timestamp` | زمن الوصول إلى معلومة موثوقة |
| فتح مسار | `place_id`, `route_id`, `timestamp` | التحويل من المحتوى إلى مسار |
| زيارة مجهّلة | `place_id`, `timestamp`, `verification_method` | معدل التوقف/الزيارة |
| تقييم الوصول | `place_id`, عناصر الوصول، `rating`, `timestamp` | تغطية الوصول الشامل |
| تفاعل مزود | `provider_id`, `interaction_type`, `timestamp` | نشاط المزودين والتحويل التجاري |

## ما يجب عدم فعله

لا يجوز ملء مؤشرات Canvas بأرقام يدوية مثل `20%` أو `35 دقيقة` ثم تسميتها قياسًا. ولا يجوز اعتبار بيانات البلاغات دليلًا على أن الزوار توقفوا أو اشتروا أو تحسنت تجربتهم. كل مؤشر يحتاج مصدرًا وسجل تعريف ومالكًا وفترة قياس ودرجة ثقة.

## معيار نجاح المرحلة التالية

تنجح الشريحة الثانية عندما نستطيع اختيار فترة ومصدر وقناة، ثم الإجابة حسابيًا عن أسئلة مثل:

1. كم شخصًا انتقل من مشاهدة قصة إلى فتح صفحة مكان؟
2. كم شخصًا طلب معلومة موثوقة، وكم استغرق الوصول إليها؟
3. أين يتوقف المسار بين المحتوى والزيارة؟
4. هل يختلف المسار بين القنوات أو المناطق؟
5. هل توجد بيانات وصول كافية قبل وصف المكان بأنه مهيأ؟

حتى ذلك الحين، يبقى وصف المنتج الدقيق:

> **SENSE Vertical Slice 01: محرك مؤشرات بلاغات قابل لإعادة التشغيل، يثبت البنية التحليلية ولا يثبت بعد أثر السياحة أو الاقتصاد المحلي.**
