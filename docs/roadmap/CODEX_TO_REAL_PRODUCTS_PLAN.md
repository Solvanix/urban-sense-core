# خطة Codex إلى منتجات SenseCity الواقعية

## الغرض

نريد استخدام Codex كأداة تدريب وتنفيذ داخل مستودع `urban-sense-core`، لكن التدريب ليس غايته إنتاج صفحات أو عروض. الغاية هي أن يتعلم الفريق كيف يفحص فكرة أو تجربة موجودة، يثبتها في GitHub، ثم يحول الجزء القابل للقيمة منها إلى منتج رقمي حقيقي تديره وكالة SENSE البرمجية مع شركاء واضحين.

> **كل تجربة تبدأ كفكرة أو موقع، ثم تمر بالدليل والاختبار والشراكة قبل أن تصبح منتجًا نستثمر فيه.**

## المبدأ الحاكم

لا نستثمر في موضوع لأنه جميل أو وطني أو حصل على مشاهدات، ولا نعتبر موقعًا منتجًا لأنه منشور على الويب. الاستثمار يأتي بعد إثبات أربع نقاط: وجود مشكلة حقيقية، مستخدم محدد، سلوك أو خدمة قابلة للتشغيل، ومسؤول قادر على الاستمرار.

## المرحلة الأولى: تدريب Codex داخل المستودع

### الهدف

تعليم الفريق دورة عمل آمنة وقابلة للتكرار داخل GitHub، لا تعليم أوامر منفصلة.

### طريقة التدريب

يعمل المتدرب داخل نسخة فرعية من `urban-sense-core`، ويبدأ بقراءة `README.md` و`todo.md` وبنية التطبيقات. لا يسمح له بتعديل الإنتاج أو دفع التغييرات مباشرة إلى `main` في التمارين الأولى.

| الوحدة | المخرج القابل للفحص |
|---|---|
| فهم المستودع | خريطة للتطبيقات، المسارات، البيانات، الاختبارات، والحدود. |
| قراءة كود قائم | تقرير يشرح ملفًا وميزة ومسار استخدامها دون تعديل. |
| تعديل صغير | Pull Request أو commit محدود مع سبب واضح. |
| الاختبار | اختبارات جديدة أو محدثة، مع نتيجة تشغيل موثقة. |
| الأمان والخصوصية | قائمة بالبيانات الخاصة، ومخاطر التسريب، وحالات الرفض. |
| الوصول والإتاحة | اختبار لوحة المفاتيح، النص البديل، التباين، واتجاه العربية. |
| النشر والمراجعة | تقرير يوضح الفرق، وما بُني، وما لم يُبنَ، وما يحتاج موافقة. |

### قواعد الصلاحيات

يعمل Codex داخل مجلد المشروع المصرح به فقط. لا تُحفظ مفاتيح API أو كلمات المرور أو بيانات الأفراد في المستودع. كل تعديل كبير يحتاج مراجعة بشرية من قائد تقني، وكل تغيير متعلق ببيانات حساسة أو نشر عام يحتاج موافقة مالك المنتج.

## المرحلة الثانية: جرد مواقع وتجارب المدرب

لا نستنتج قيمة المواقع من الاسم أو الانطباع. نطلب قائمة الروابط، ثم نملأ لكل موقع بطاقة:

| الحقل | ما نتحقق منه |
|---|---|
| الرابط والمالك | هل الرابط عام؟ من يملك النطاق والحساب والكود؟ |
| الموضوع | ما القضية أو المعرفة أو الخدمة التي يعالجها؟ |
| المستخدم | من يدخل الموقع، وما الذي يستطيع فعله؟ |
| نوع الأصل | صفحة تعريف، موقع محتوى، تجربة تفاعلية، أو منتج. |
| الدليل | زيارات أو استخدام أو طلبات أو شراكات موثقة، إن وجدت. |
| التقنية | كيف بُني؟ وهل يمكن صيانته وتوسيعه؟ |
| المحتوى | هل هو دائم وموثق أم مرتبط بورشة مؤقتة؟ |
| الإتاحة | هل يمكن استخدامه على الهاتف ولوحة المفاتيح وبالعربية؟ |
| البيانات | ما الذي يجمعه؟ أين يخزنه؟ ومن يملك حق الوصول؟ |
| الاستمرارية | من يحدثه ويموله ويديره بعد النشر؟ |

الهدف من الجرد ليس تقييم الشخص فقط، بل اكتشاف **المواضيع التي يمكن أن تصبح خطوط منتجات** داخل وكالة SENSE.

## المرحلة الثالثة: تحويل الموضوع إلى فرصة منتج

نحوّل كل موقع إلى بطاقة قرار، لا إلى وعد استثماري. البطاقة تجيب عن الأسئلة الآتية:

1. ما المشكلة المتكررة التي يحاول الموضوع حلها؟
2. من المستخدم الذي يعانيها، ومن سيدفع أو يشغل الحل إن احتاج تمويلًا؟
3. ما الذي يمكن فعله داخل المنتج، لا قراءته فقط؟
4. ما الشريك الذي يملك الوصول أو الخبرة أو البيانات؟
5. ما أقل نسخة يمكن اختبارها خلال دورة قصيرة؟
6. ما الضرر المحتمل إذا أخطأنا أو نشرنا بيانات غير دقيقة؟
7. ما دليل النجاح الذي نستطيع قياسه دون اختلاق أرقام؟

## المرحلة الرابعة: مصفوفة اختيار الموضوعات

تستخدم الوكالة مقياسًا من صفر إلى خمسة لكل معيار. لا تعني الدرجة العالية قرار استثمار تلقائي؛ بل تعني أولوية للفحص.

| المعيار | سؤال التقييم | الوزن المقترح |
|---|---|---:|
| الحاجة | هل توجد مشكلة واضحة ومتكررة؟ | 20% |
| قابلية التنفيذ | هل يمكن بناء MVP بموارد الفريق الحالية؟ | 15% |
| قابلية الاستخدام | هل يوجد مستخدم يستطيع تنفيذ فعل حقيقي؟ | 15% |
| الأثر الوطني/الاجتماعي | هل يخدم قضية معتبرة دون استغلالها؟ | 15% |
| ملاءمة SENSE | هل يرتبط بالاستقلال أو الإتاحة أو المدينة أو المعرفة أو السياحة أو السكن؟ | 10% |
| الشريك التشغيلي | هل يوجد طرف يستطيع تشغيل الحل أو اختباره؟ | 10% |
| الثقة والخصوصية | هل يمكن حماية البيانات والتحقق من الادعاءات؟ | 10% |
| الاستدامة | هل توجد طريقة معقولة للصيانة والتمويل والاستمرار؟ | 5% |

### بوابات القرار

| النتيجة | القرار |
|---|---|
| أقل من 2.5 | لا نستثمر الآن؛ نحفظ الفكرة ونطلب معلومات إضافية. |
| من 2.5 إلى أقل من 3.5 | بحث أو نموذج أولي محدود، دون إعلان منتج. |
| من 3.5 إلى أقل من 4.25 | تجربة Pilot مع شريك ومؤشر نجاح واضح. |
| 4.25 فأكثر | إعداد دراسة جدوى فنية وتشغيلية ومالية قبل قرار الاستثمار. |

## المواضيع الأولى التي تستحق الفحص

لا نختار نهائيًا قبل رؤية روابط مواقع المدرب، لكن يمكن ترتيب الفئات الأولية بحسب اتصالها بما بُني في SenseCity:

| الفئة | سبب الفحص | المنتج المحتمل |
|---|---|---|
| **المعرفة الوطنية والذاكرة** | مناسبة للمقالات والأرشفة والمحتوى الدائم، لكن تحتاج مصادر وحقوق نشر. | مكتبة معرفة أو تجربة أرشيفية موثقة. |
| **الإتاحة ومسارات الاستقلال** | لها صلة مباشرة بالتطبيق الموجود وبميثاق الإدماج. | أداة تخطيط أو دليل وصول قابل للمراجعة، لا دليل عام غير موثق. |
| **السياحة المسؤولة** | توجد بنية استبيان وExperience Studio وسجل ادعاءات. | بطاقة تجربة مزود مع فصل البيانات الخاصة عن الإسقاط العام. |
| **السكن الاجتماعي ومساكن الخير** | لها مساحة مبادرة ولوحة جاهزية، لكنها تحتاج مالكًا تشغيليًا وشركاء عقار. | بوابة التزام ومطابقة بعد التحقق، لا سوق مساكن جاهز قبل الشروط. |
| **التعليم أو الورش** | مناسبة لتحويل المعرفة إلى مسار عملي، لا إلى نسخة دورات فقط. | مساحة مشروع وتطبيق وملف أعمال، مع مالك محتوى وصيانة. |

هذه فئات فحص وليست قائمة استثمار معتمدة. لا نعطي أولوية نهائية قبل جرد المواقع وسؤال المستخدمين والشركاء.

## المرحلة الخامسة: تحويل التجربة إلى واقع

يمر كل موضوع بدورة تطوير ثابتة:

> **فكرة المدرب أو الموقع → مراجعة المشكلة → مقابلات أو اختبار مع أصحاب التجربة → مواصفة منتج → Prototype → MVP → Pilot مع شريك → قياس → قرار استثمار أو إيقاف.**

الفريق التقني مسؤول عن الهندسة والبيانات والأمان والاختبارات. منشئ المحتوى أو الوكالة مسؤول عن الفكرة واللغة والمادة المرئية والتوثيق. مسؤول العلاقات مسؤول عن الشركاء والموافقات وقناة التشغيل. صاحب القضية أو المؤسسة الشريكة يراجع الحقيقة ويملك القرار المتعلق بخدمته أو أرشيفه.

## ما الذي نعتبره «استثمارًا»؟

الاستثمار ليس فقط دفع المال. قد يكون تخصيص وقت الفريق، شراء نطاق أو خدمة، تمويل إنتاج، اتفاق شراكة، أو التزام جهة بتشغيل المنتج. لذلك نسجل لكل مشروع:

- الموارد المطلوبة.
- مالك المنتج.
- الشريك التشغيلي.
- المستخدم الأول.
- المخرج خلال الدورة الأولى.
- مخاطر الخصوصية والسمعة.
- معيار الاستمرار أو الإيقاف.
- مصدر التمويل أو نموذج الإيراد إن وجد.

لا نضع توقعات مالية أو عوائد قبل جمع بيانات حقيقية عن التكاليف والطلب والقدرة على التشغيل.

## مخرجات الوكالة بعد كل تجربة

تسلم الوكالة حزمة واحدة تشمل: صفحة القضية، نسخة المحتوى الدائم، فيديو جوال مناسب، نموذج المنتج، خريطة المستخدم، سجل الأدلة، تقرير الإتاحة، تقرير الخصوصية، رابط GitHub، وقرار المرحلة التالية. بهذه الطريقة لا يبقى العمل في ملف إعلامي أو موقع منفصل، بل يصبح أصلًا قابلًا للفحص داخل المنظومة.

## القرار المطلوب الآن

نحتاج أولًا إلى روابط المواقع أو التجارب التي بناها المدرب، وبيان ما إذا كان يملك الكود والحسابات والنطاقات أم لا. بعد ذلك نختار موضوعين فقط: أحدهما قريب من منتج SenseCity قائم، مثل مسار الاستقلال أو السياحة المسؤولة، والآخر يختبر قدرة الوكالة على إنتاج محتوى/تجربة وطنية دائمة. ثم نعرض النتيجة على الفريق التقني والشركاء قبل أي استثمار أوسع.

> **لا نريد أن ننتج مواقع أكثر؛ نريد أن نكتشف أي موقع يخفي وراءه مشكلة حقيقية ومنتجًا قابلًا للحياة، ثم نبنيه بطريقة مسؤولة.**
