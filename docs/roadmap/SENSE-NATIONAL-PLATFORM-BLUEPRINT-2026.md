# SENSE National — مخطط منصة وطنية للوجهات

**الإصدار:** 1.0 — سبتمبر 2026

**الحالة:** قرار اتجاهي ومخطط منتج، وليس اعتمادًا حكوميًا أو شراكة وطنية مثبتة.

## القرار

SENSE ليست منصة العيزرية فقط. العيزرية هي **Pilot 01** اختُبرت فيه الفكرة: قصة مرتبطة بمكان، وبطاقة مسار، وحالة وصول، ومالك معلومة، وخطوة تحقق تالية.

المنتج المقصود هو منصة وطنية متعددة الوجهات تساعد الزائر والمجتمع المحلي والجهة العامة على الانتقال من:

```text
قصة محلية → مكان → مسار → تجربة → منفعة محلية → قياس وتعلم
```

ولا تعني الوطنية أن كل شيء مركزي أو أن منصة واحدة تملك روايات المدن. تعني وجود **معايير مشتركة**، مع بقاء ملكية المحتوى والمراجعة والقرار عند الوجهة وأصحابها.

## ما الذي يبقى من العيزرية؟

تبقى العيزرية مختبرًا حيًا لتصميم:

- بطاقة الثقة.
- جواز الرحلة.
- قواعد الخصوصية وحق الانسحاب.
- ربط WordPress بالقصة وGitHub بالحالة.
- اختبار الصلاحيات والعزل البلدي.
- بوابة الانتقال من قصة تحريرية إلى تجربة قابلة للتشغيل.

لا تُنسخ أسماء العيزرية أو ادعاءاتها إلى وجهة أخرى. الذي ينتقل هو **النظام والمنهج والعقد**، لا المحتوى المحلي.

## بنية المنصة الوطنية

| الطبقة | الوظيفة | الملكية المقترحة |
|---|---|---|
| الهوية الوطنية | اسم المنصة، المعايير، قاموس الحالات، التصميم الأساسي | SENSE / الجهة الحاكمة لاحقًا |
| ملفات الوجهات | مدينة، قرية، موقع، منطقة، لغة، وصف وسياق | الوجهة ومالك المحتوى |
| القصص | تقارير وذاكرة ومقابلات ومصادر | المحرر وصاحب الرواية |
| المسارات | تجربة قصيرة بمدة ووصول وحالة ومضيف | مالك المسار والجهة المراجعة |
| الثقة | مصدر، مالك، تاريخ، موافقة، درجة جاهزية إرشادية | سجل مشترك قابل للمراجعة |
| التجارب المحلية | مزود، سعة، سعر، سياسة، إتاحة، تواصل | صاحب الخدمة بعد الموافقة |
| البلدية | مراجعة عامة، سلامة، ملكية، بيانات نطاقها | البلدية أو الجهة المفوضة |
| القياس | فهم البطاقة، الانتقال، الاستخدام، الاعتراض، المنفعة | مشترك مع حدود الخصوصية |
| التكاملات | خرائط، نقل، QR/NFC، WordPress، APIs | حسب التكامل والعقد |

## نموذج الوجهة

كل وجهة وطنية تحتاج معرفًا مستقلًا، ولا تضاف إلى النشر العام قبل اكتمال الحد الأدنى التالي:

```json
{
  "destinationId": "DEST-001",
  "country": "PS",
  "region": "",
  "name": "",
  "localNames": [],
  "status": "candidate",
  "contentOwner": "",
  "reviewOwner": "",
  "languages": ["ar"],
  "routes": [],
  "stories": [],
  "lastReviewed": "",
  "dataStatus": "prototype"
}
```

## حالات الوجهة

- `candidate`: فكرة مرشحة، بلا نشر سياحي عام.
- `researching`: جمع مصادر وأصوات ومخاطر.
- `pilot`: مسار أو مساران مع اختبار محدود.
- `reviewed`: محتوى ومسارات راجعها مالك معلوم.
- `public`: صفحة عامة مع حدود واضحة.
- `paused`: موقوفة بسبب سلامة أو ملكية أو اعتراض أو تقادم.

هذه الحالات لا تعني اعتمادًا سياحيًا أو بلديًا. إنها حالات تشغيل محتوى ومنتج فقط.

## قواعد التوسع

1. **وجهة واحدة لا تكفي للمنصة الوطنية، لكنها تكفي لاختبار النظام.**
2. **لا نضيف منطقة جديدة لمجرد زيادة عدد البطاقات.** يجب أن تملك مالك محتوى ومراجعًا ومخرج Pilot.
3. **لا مركزية الرواية:** لكل مجتمع حق التصحيح والاعتراض والانسحاب.
4. **مركزية المعايير فقط:** معرفات، حالات، حقول، اختبارات، وحواجز أمان.
5. **الفصل البلدي:** لا تستطيع بلدية أو مراجع قراءة أو تعديل نطاق بلدية أخرى دون تفويض صريح.
6. **لا نقل للادعاءات:** مصدر مدينة لا يثبت ادعاء مدينة أخرى.
7. **لا حجز وطني قبل التشغيل المحلي:** الحجز يحتاج مزودًا وسياسة وسعة ووقتًا وتواصلًا.
8. **لا NFC أو محفظة أو نقل ذكي قبل إثبات قيمة QR/التطبيق والمسار.**

## حزمة إطلاق لكل وجهة

قبل فتح وجهة جديدة، تُجهّز الحزمة التالية:

- بطاقة تعريف الوجهة.
- خريطة مصادر لا تنشر المواقع الحساسة دون مبرر.
- قصة افتتاحية واحدة.
- مساران أو ثلاثة بحدود واضحة.
- ملفي جاهزية لمضيفين أو أصحاب تجربة إن توفرا.
- سجل أصحاب المصلحة والاعتراضات.
- مراجعة وصول وخصوصية.
- مؤشرات Pilot محدودة.
- خطة إيقاف أو تحديث.

## الطريق التقني

### المرحلة A — النظام الوطني القابل للعرض

- معرف وجهة في عقد البيانات.
- فهرس وطني يميز الوجهة والحالة.
- صفحة لكل وجهة لا تعتمد على نسخ HTML يدوي.
- بطاقات مسارات مرتبطة بـ`destinationId`.
- فلاتر حسب الوجهة والمنطقة ونوع التجربة.

### المرحلة B — Pilotات متعددة

- وجهة أولى مكتملة: العيزرية.
- وجهة ثانية مختلفة في نوع المشكلة، لا نسخة جغرافية مشابهة.
- مقارنة فهم البطاقات، جودة المصدر، والاعتراضات.
- اختبار عزل بلدي بين نطاقين.

### المرحلة C — شبكة مراجعة

- أدوار: محرر، مالك تجربة، مراجع بلدي، مراجع وصول، مدير منصة.
- سجل تدقيق.
- طلبات مراجعة وإيقاف.
- تحديثات مؤرخة وإشعارات تقادم.

### المرحلة D — التكاملات

- تطبيق زائر أو PWA بعد ثبوت تدفق القصة إلى المسار.
- Offline-first عند وجود حاجة ميدانية حقيقية.
- QR تجريبي قابل للإبطال.
- NFC فقط بعد مقارنة قيمة واضحة مع QR.
- محفظة أو دفع أو بوابات دخول خارج نطاق هذه المراحل حتى توجد متطلبات وملكية واعتمادات.

## نموذج الحوكمة

| القرار | صاحب القرار الأول | ما يحتاجه |
|---|---|---|
| نشر قصة | المحرر ومالك الرواية | مصدر/موافقة/تاريخ |
| نشر مسار عام | مالك المسار والمراجع | وصول/خصوصية/حدود |
| رفع الحالة إلى Pilot | لجنة Pilot محلية | اختبار ومخرج واضح |
| إدراج حجز | صاحب الخدمة والمشغل | سعة/سعر/تواصل/سياسة |
| إيقاف مسار | مالك القرار أو اعتراض موثق | سبب وتاريخ وخطة تحديث |
| معيار وطني | حوكمة SENSE | مراجعة أثره على الوجهات |

## مؤشرات وطنية لا تتحول إلى vanity metrics

- عدد الوجهات ذات مالك مراجعة معلوم.
- نسبة البطاقات التي تحتوي مصدرًا وتاريخًا.
- نسبة المسارات التي تملك حدود وصول واضحة.
- قدرة الزائر على تفسير حالة المسار.
- عدد التصحيحات والاعتراضات التي عولجت.
- زمن تحديث بطاقة متقادمة.
- وجود منفعة محلية قابلة للشرح، لا مجرد عدد نقرات.
- فرق الفهم بين وجهتين أو جمهورين، لا عدد الزيارات وحده.

## ما لا ندّعيه الآن

- لا توجد شبكة وطنية مفعلة أو جهة حكومية متعاقدة.
- لا توجد قاعدة بيانات وطنية مكتملة.
- لا توجد حجوزات وطنية أو محفظة وطنية.
- لا تمثل GitHub Pages سجلًا رسميًا للمعالم أو الملكيات.
- لا يمثل MABA Bridge تشغيلًا للأجهزة أو المال.
- لا يجوز استخدام اسم SENSE لإسناد شراكة لم توافق عليها جهة.

## القرار التنفيذي التالي

لا نبدأ ببناء «سوق سياحي وطني» شامل. نبدأ ببناء **قالب وجهة وطني قابل للتكرار**، ثم نختبره في:

1. العيزرية — Pilot 01، قصة وذاكرة وخصوصية ومسارات حساسة.
2. وجهة ثانية مختلفة في طبيعتها، لاختبار قابلية النقل.
3. نطاق بلدي ثانٍ لاختبار العزل والصلاحيات.
4. مقارنة مشتركة قبل فتح فهرس وطني عام.

بهذا تصبح العيزرية بداية مقنعة، لا قفصًا استراتيجيًا.
