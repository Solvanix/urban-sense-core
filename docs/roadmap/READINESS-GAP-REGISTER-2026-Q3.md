# سجل الجاهزية والفجوات — الربع الثالث 2026

## الخلاصة التنفيذية

يحدد هذا السجل حالة القدرات الرئيسية في منظومة SENSE وUrban‑Sense داخل المستودع المرجعي `urban-sense-core`. الغرض منه منع مساواة وجود واجهة أو كود بحالة الجاهزية التشغيلية. تُصنَّف كل قدرة وفق العائق الذي يمنع توسيعها: **جاهزة للبناء**، أو **تحتاج سياسة**، أو **تحتاج مصدر بيانات**، أو **تحتاج شريك تشغيل**.

السجل لا يعلن اعتمادًا مؤسسيًا أو أثرًا ميدانيًا. فالشريحة التحليلية الحالية تستخدم بيانات اصطناعية قابلة لإعادة التشغيل، وتبقى الخدمات التي تتعامل مع بيانات حقيقية مقيدة حتى اكتمال شروط الهوية والخصوصية والمراجعة والتشغيل.

## تعريف الحالات

| الحالة | معناها العملي | ما لا تعنيه |
|---|---|---|
| جاهزة للبناء | المتطلبات الأساسية مفهومة، ويمكن تنفيذ شريحة اختبارية معزولة دون بيانات إنتاج | ليست جاهزية للإطلاق العام |
| تحتاج سياسة | يوجد كود أو تصور، لكن قرار قانوني أو تشغيلي أو حوكمي مطلوب قبل التفعيل | لا يجوز تجاوز السياسة بالتنفيذ التقني |
| تحتاج مصدر بيانات | لا يوجد مصدر موثق بمالك وتواتر وتاريخ تحديث وتعريف للمؤشر | لا يجوز ملء الفراغ بأرقام نموذجية |
| تحتاج شريك تشغيل | يتطلب المسار بلدية أو مزودًا أو مراجعًا أو جهة قانونية محددة | لا يجوز تقديمه كخدمة مكتملة |
| محجوزة/مؤجلة | النطاق غير مناسب للربع الحالي أو يعتمد على قرار سابق لم يُحسم | لا تعني إلغاء الفكرة |

## السجل الموحد

| القدرة | الحالة الحالية | الدليل الموجود في المستودع | بوابة التفعيل التالية | مالك القرار المطلوب |
|---|---|---|---|---|
| البلاغ الحضري من الاستقبال إلى الإغلاق | جاهزة للبناء | تطبيق `apps/web`، مخطط البيانات، الاختبارات، وVisualizer | تجربة مغلقة ببيانات اصطناعية ثم بيانات بلدية معتمدة | مالك تشغيل بلدي |
| شريحة مؤشرات البلاغات | جاهزة للبناء | `analytics/vertical_slice` و`visualize/data/dashboard.json` | اعتماد مصدر بيانات حقيقي وتعريف المؤشرات | مالك بيانات ومراجع مؤشرات |
| بوابة SENSE العامة ومسارات البلديات | جاهزة للبناء | صفحات البوابة ومسارات `كيف تعمل` و`للبلديات` والاختبارات | مراجعة محتوى وروابط قبل النشر الموسع | مالك المنتج التحريري |
| غرفة التحقق وسجل الادعاءات | جاهزة للبناء | `VerificationRoom` وسجل الأدلة وإجراءات المراجع | تعيين مراجع بشري وسياسة نشر واحتفاظ | مسؤول التحرير والحوكمة |
| SENSE Experience وبطاقة المكان | تحتاج سياسة | `apps/sense-experience` وبطاقات التجربة وإعدادات الوصول | اعتماد قائمة الحقول البيضاء، سياسة الخصوصية، ومسار المراجع | مسؤول الخصوصية والمنتج |
| إدخال ملفات المزودين | تحتاج عقد تخزين | واجهة المزود وعقد المراجعة، دون رفع إنتاجي | عقد تخزين خاص، فحص نوع وحجم الملف، عزل الصلاحيات، وسياسة احتفاظ | مالك البنية والأمن |
| اقتراحات الذكاء الاصطناعي التحريرية | تحتاج سياسة | خطة AI Commander ونموذج المحتوى التحريري | تعريف المسودة، سجل المراجعة، منع النشر التلقائي، وسياسة الاحتفاظ | مسؤول التحرير والحوكمة |
| الخريطة الحية والتنقل | تحتاج مصدر بيانات | نماذج Visualizer وروابط تجريبية | مصدر خرائط موثق، سياسة دقة الموقع، واختبار وصول | مالك بيانات الخرائط وشريك تنقل |
| الحجز والمتجر والتسويات | تحتاج شريك تشغيل | نماذج وتصاميم أولية فقط | مزود دفع أو شريك مرخص، سياسة إلغاء واسترداد، ومصدر حقيقة للطلب | مسؤول مالي وقانوني |
| مساكن الخير | تحتاج شريك تشغيل | التطبيق التجريبي ومركز القيادة وبوابة الإطلاق | اعتماد المدينة والفئة وشريك الإحالة والجهة القانونية والتمويل | لجنة البرنامج والشريك القانوني |
| مسار الاستقلال | تحتاج شريك تشغيل | تطبيق الخطة الشخصية والحفظ المحلي والطباعة | اختبار تشاركي واعتماد شريك إحالة وعدم جمع تشخيصات | مسؤول البرنامج وشريك تمكين |
| اختبارات الإتاحة التشاركية | تحتاج شريك تشغيل | اختبارات آلية للوصول ولوحة المفاتيح | جلسات مع أشخاص ذوي إعاقة ومختصين وتوثيق النتائج | دائرة خبرة تمثيلية |
| المحاسبة الداخلية | محجوزة/مؤجلة | متطلبات أولية في `todo.md` فقط | اعتماد نموذج الملكية والتمويل ثم مخطط دفتر الحسابات | محاسب ومراجع قانوني |
| تشغيل Docker مستقل | جاهزة للبناء | `Dockerfile` و`compose.yaml` وتعليمات النشر | خادم تملكه الجهة، إعدادات خارج Git، وفحص صحة مسجل | مالك البنية التحتية |

## مسار الربع الثالث 2026

يُنفَّذ المسار على مراحل قصيرة، ولا تنتقل مرحلة إلى التالية إذا بقيت بوابة السلامة السابقة مفتوحة.

| الفترة | الهدف | المخرجات القابلة للتحقق | شرط الانتقال |
|---|---|---|---|
| الأسبوع 1 | تثبيت المصدر المرجعي | `main` محدث، فحوص GitHub ناجحة، وسجل فجوات واحد | لا توجد تغييرات غير موثقة في المصدر |
| الأسبوع 2 | تثبيت الشريحة التحليلية | إعادة تشغيل التحليل، تعريف كل مؤشر، ووسم البيانات الاصطناعية | لا يُعرض أي رقم بوصفه قياسًا ميدانيًا |
| الأسبوع 3 | مراجعة التحرير والادعاءات | قصة واحدة كمسودة، سجل مصادر، ومراجع بشري | لا نشر عام قبل اكتمال سجل المصدر والموافقة |
| الأسبوع 4 | عقد رفع الملفات | تصميم العقد، حدود الحجم والنوع، واختبارات العزل | موافقة الأمن والخصوصية على التخزين |
| الأسبوع 5–6 | اختبار الوصول التشاركي | جلسات اختبار موثقة ونتائج إصلاح | عدم استخدام وصف «معتمد» قبل المراجعة المتخصصة |
| الأسبوع 7–8 | تجربة تشغيل مغلقة | نطاق واحد، شريك تشغيل محدد، بيانات اصطناعية أو مصرح بها، وخطة تراجع | مالك تشغيل مسمى وقناة دعم واضحة |
| الأسبوع 9–10 | قرار الخريطة والتنقل | مصدر بيانات، تعريف الدقة، ونموذج إفصاح للمستخدم | لا خريطة حية دون مصدر محدث ومالك |
| الأسبوع 11–12 | بوابة قرار التوسع | تقرير نتائج، قائمة مخاطر، وتوصية بالاستمرار أو الإيقاف | قرار مكتوب قبل إضافة التجارة أو الحجوزات |

## قواعد القرار والتحديث

كل تغيير في قدرة مسجلة يجب أن يذكر أثره على البيانات، والصلاحيات، والترحيلات، والاختبارات، والتراجع. تُراجع الحالات في نهاية كل أسبوعين، ويُسجل تاريخ التحديث وسبب الانتقال واسم المالك في الالتزام أو وثيقة قرار مرتبطة.

لا يُنقل أي عنصر إلى «جاهزة للبناء» لمجرد وجود تصميم. ولا يُنقل إلى «جاهزة للإطلاق» إلا بعد وجود مصدر بيانات أو شريك تشغيل وسياسة مناسبة واختبارات قابلة لإعادة الإنتاج.
