# خارطة تطوير GitHub-first — Urban‑Sense

يُعامل المستودع `Solvanix/urban-sense-core` بوصفه المصدر الأساسي للعمل. تبقى نسخة Manus المنشورة مرجعًا بصريًا وتشغيليًا حتى تتم مزامنة التحسينات إلى المستودع واختبارها ودفعها إلى الفرع `main`.

## الحالة المؤكدة

| المجال | النتيجة |
|---|---|
| الفرع الرئيسي | `main` عند الالتزام `300f894915e24f80ef65c0c42e2855424d939a5c`. |
| فحص الجودة المحلي | `pnpm check` و`pnpm test` و`pnpm build` ناجحة: 18 اختبارًا في 4 ملفات. |
| الفجوة العامة | النسخة المنشورة تحتوي رأسًا وتذييلًا وصفحتي «كيف تعمل؟» و«للبلديات» واختبار تنقل عام، وهي غير موجودة بعد في المستودع. |
| الملاحظة التقنية | بناء الإنتاج ينجح مع تحذير حجم حزمة JavaScript؛ يؤجل التقسيم الديناميكي إلى مرحلة أداء منفصلة. |

## قرارات الهوية

تثبت الهوية الحالية على «المكان، المسار، والأثر»: أخضر بلدي داكن، ذهبي هادئ، ونمط مسار بلاغ يوضح الاستلام والمراجعة والتنفيذ والتحقق. لا تُنقل لغة SENSE Urban الزرقاء–الذهبية أو نطاق السياحة والمتجر إلى Urban‑Sense؛ يؤخذ منها فقط مبدأ الإفصاح عن حدود الخدمة وإتاحة الاستخدام.

## التنفيذ الأول

1. نقل بنية التنقل العام والصفحات التعريفية من النسخة المراجعة إلى المستودع، مع الحفاظ على مسارات البلاغات والعمليات الحالية.
2. إضافة اختبار وحدات صغير يثبت أن عناصر التنقل العام تحافظ على مساراتها.
3. ربط الصفحة العامة بخطوات البلاغ الحقيقية، وبنطاق التجربة غير الطارئ، وبمسار البلديات من دون أرقام أو ادعاءات نتائج.
4. تشغيل النوع والاختبارات والبناء، ثم توثيق فرق الملفات والالتزام والدفع إلى GitHub.

## عناصر لاحقة لا تدخل هذا الالتزام

إعدادات الوصول المتقدمة، خريطة البلاغات العامة، الإشعارات، القياسات المجمعة، وتقسيم الحزمة تُناقش بعد اكتمال التحديث العام ووجود بيانات تشغيلية حقيقية.
