# SENSE WordPress Handoff v1

## الغرض

هذا الملف يحوّل حزمة SENSE إلى خطة إدخال عملية في WordPress باستخدام قالب **Blocksy** ومحرر Gutenberg. يحتفظ GitHub بالمصدر والوثائق والأصول، بينما يحتفظ WordPress بالنسخة المحررة والمسودات والنشر.

## قاعدة التشغيل

لا تُنشر مادة بوصفها واقعة ميدانية أو خدمة متاحة ما لم تُراجع بشريًا. لا تُضاف أسعار أو حجوزات أو مواعيد أو بيانات حرفيين دون مصدر ومالك وتاريخ تحديث. لا تُحفظ كلمات المرور أو رموز WordPress أو مفاتيح API في GitHub.

## المرحلة 0: قبل الدخول

- تأكيد رابط موقع WordPress واسم الموقع النهائي.
- التأكد من وجود صلاحية إدارة أو تحرير مناسبة.
- تثبيت Blocksy Free فقط.
- ضبط اللغة العربية واتجاه RTL.
- إنشاء نسخة احتياطية قبل أي استيراد أو تغيير كبير.
- عدم تفعيل الدفع أو الحجوزات في الإصدار الأكاديمي الأول.

## المرحلة 1: إعداد Blocksy

1. Appearance → Themes → تثبيت Blocksy وتفعيله.
2. Appearance → Customize أو Site Editor حسب نسخة WordPress.
3. ضبط الألوان من `sense-brand-tokens.json`:
   - Night Story: `#17211F`
   - Olive Place: `#66734A`
   - Stone Jerusalem: `#E7DED0`
   - Light Gold: `#C79A4A`
   - Warm Clay: `#A7654B`
   - Paper White: `#FAF8F3`
4. ضبط الخط العربي إلى IBM Plex Sans Arabic أو Noto Sans Arabic، مع اختبار الحروف العربية على الهاتف.
5. ضبط التخطيط على RTL، عرض قراءة متوسط، وعناوين واضحة.
6. إنشاء رأس الموقع: شعار SENSE، وصف قصير، قائمة RTL، وزر «ابدأ اكتشافك».
7. إنشاء تذييل يحتوي على المصادر والحقوق، عن SENSE، وسطر حالة المحتوى.

## المرحلة 2: الصفحات

أنشئ الصفحات وفق `wordpress-sense-site-structure.json` وبالترتيب التالي:

1. الرئيسية — صفحة ثابتة.
2. التحرير — صفحة فهرس.
3. اكتشف — صفحة فهرس.
4. المتجر الوطني — صفحة حالة ومقدمة، وليس متجر دفع كاملًا في الإصدار الأول.
5. قصص الحرفيين — صفحة فهرس.
6. سهولة الوصول.
7. عن SENSE.
8. المصادر والحقوق.
9. العيزرية.
10. المعالم.
11. المسارات.
12. القصة المصورة.
13. الفيديو والصوت.

## المرحلة 3: المقالات

أنشئ تصنيفين رئيسيين:

- `التحرير`: القصص والتقارير والمواد الإعلامية.
- `الوجهات`: العيزرية والمعالم والمسارات.
- `الحرفيون`: قصص الحرفيين والمنتجات المرتبطة بهم.

أنشئ المقالتين كمسودتين:

- **الكنز الذي مررنا بجانبه** — من `SENSE-editorial-academic-pack.md`.
- **لماذا لا تتحول المعالم المحلية إلى تجارب سياحية؟** — من الملف نفسه.

استخدم لكل مقال:

- عنوانًا واضحًا.
- عنوانًا فرعيًا.
- مقدمة قصيرة.
- عناوين فرعية داخلية.
- صورة بارزة مع Alt Text.
- صندوق مصادر وحقوق.
- حالة تحريرية ظاهرة: «مسودة جاهزة للتحرير الميداني».

## المرحلة 4: الوسائط

ارفع الصور الموجودة في `assets/wordpress-sense/` مع البيانات الموجودة في `media-manifest.csv`. لا تقدم الصور المولدة كصور توثيق ميداني. عند استبدالها بصور ميدانية، حدّث المصدر والحقوق والوصف البديل.

## المرحلة 5: الوسائط التفاعلية

### الفيديو

أضف كتلة Video أو YouTube فقط بعد توفير فيديو من إنتاج الفريق أو رابط مرخص. أضف ملخصًا نصيًا أسفل الفيديو، ولا تجعل الفيديو المصدر الوحيد للمعلومة.

### التسجيل الصوتي

أضف كتلة Audio بعد أخذ موافقة المتحدث. أضف تفريغًا نصيًا كاملًا، واذكر اسم المتحدث ودوره وتاريخ التسجيل إذا وافق على ذلك.

### الخريطة

أضف رابط خريطة أو خريطة مضمّنة بعد التحقق الميداني. يجب أن تشرح الصفحة حدود الدقة، وإمكانية الوصول، وتاريخ آخر تحقق.

### الإنفوغراف

أضف الرسم كصورة مع شرح نصي بديل يقرأه قارئ الشاشة. لا تعتمد على الألوان وحدها لتمييز الحالات.

## المرحلة 6: فحص النشر

- افتح الموقع في الهاتف وسطح المكتب.
- اختبر اتجاه RTL والقائمة والروابط.
- تنقل باستخدام لوحة المفاتيح فقط.
- تحقق من ظهور النص البديل أو وصف الصورة.
- تحقق من تباين النص والأزرار.
- تحقق من عمل الفيديو والصوت أو بقاء عناصرهما كمسودات واضحة.
- تحقق من وجود المصادر والحقوق.
- تحقق من عدم وجود سعر أو حجز أو توفر غير مؤكد.
- احفظ نسخة من النصوص والصور خارج WordPress.

## المرحلة 7: الربط مع GitHub لاحقًا

الإصدار الأول يعتمد إدخالًا يدويًا واضحًا: GitHub → مراجعة → WordPress Draft → مراجعة الهاتف → Publish. لا نضيف مزامنة آلية قبل تحديد طريقة المصادقة، وصلاحيات WordPress، وسجل المراجعة، وآلية التراجع.

إذا أُنشئ تكامل لاحقًا، تستخدم بيانات WordPress Application Password محدودة وتُحفظ في GitHub Secrets أو مدير أسرار، ولا تُكتب في الملفات أو Issues أو المحادثات.

## معيار قبول الإصدار الأكاديمي

تظهر القصة الرئيسية والتقرير في موقع يمكن تصفحه بالعربية، ويحتوي كل منهما على صورة ووصف بديل ومصادر، مع خطة واضحة للفيديو والصوت والإنفوغراف. ويظل كل عنصر غير متوفر موسومًا بأنه «قيد التجهيز» بدل اختلاقه.

## حالة الإصدار

- GitHub: جاهز.
- Blocksy: معتمد.
- المحتوى: مسودة قابلة للإدخال.
- الصور: أصول تصميمية مولدة، تحتاج استبدالًا أو وسمًا مناسبًا عند التوثيق.
- WordPress: ينتظر رابط الموقع وصلاحية لوحة الإدارة.
- الفيديو والصوت: ينتظران إنتاجًا أو روابط مرخصة.
