# خطة تسليم مشروع Manus القادم

## 0. الغرض من الوثيقة

هذه الوثيقة هي نقطة البدء الرسمية لمشروع Manus القادم. تلخص القرارات والحقائق والحدود التي ظهرت خلال العمل على اختبار تطوير المحتوى، SENSE، TIBYAN، UrbanUP، MABA، WordPress، GitHub، Facebook، LinkedIn، وشبكات التواصل. يجب أن يقرأها Manus قبل إنشاء صفحات أو كتابة محتوى أو تنفيذ تكاملات.

الهدف ليس إطلاق كل شيء دفعة واحدة، بل بناء نظام محتوى وتجربة سياحية قابلة للتحقق، ثم إضافة الوظائف التشغيلية بعد إثبات الحاجة.

## 1. تعريف المشروع في جملة واحدة

> **SENSE هو منهج ومنصة محلية لاكتشاف الوجهات من خلال قصص أهلها ومساراتها وتجاربها ومنتجاتها، يبدأ بـPilot صغير قابل للقياس، ثم يتوسع تدريجيًا إلى تنظيم الحركة والعروض والهوية الرقمية إذا أثبت التشغيل والطلب ذلك.**

## 2. بنية الأسماء والعلامات

يجب عدم تقديم الأسماء كأنها أربعة منتجات متنافسة.

| الاسم | دوره الصحيح |
|---|---|
| SENSE | الهوية والمنهج والفريق والمنصة السياحية التحريرية |
| TIBYAN | منتج أو Pilot لتنظيم الوجهة والحركة والوصول والمحتوى |
| UrbanUP | إطار أو برنامج للابتكار الحضري والبلدي |
| أثر الحجر | نشاط تجاري فعلي للحجر والجرانيت والبورسلان وCNC وCAD/CAM والنقوش المعمارية |
| MABA NFC | مواصفة تقنية مستقبلية لهوية سياحية وخصومات ونقل ودخول، وليست دليل تشغيل حالي |
| SENSE Routes | طبقة المسارات وبطاقات الوصول والمراجعة |

### قاعدة حاسمة حول «أثر الحجر»

صفحة Facebook الموجودة باسم «أثر الحجر» هي صفحة خدمة محلية فعلية، ووصفها الحالي يدور حول الجرانيت والبورسلان والشايش وتصميم وتنفيذ CNC ومخططات CAD/CAM وCorelDRAW والنقوش المعمارية. لا تُحوّل الصفحة إلى صفحة قصص سياحية. يمكن لـSENSE إنتاج قصة منفصلة عن الحرفة بعد موافقة صاحب النشاط، ثم الربط بين القصة وصفحة الخدمة.

## 3. ما تم إثباته وما لم يُثبت

### المثبت داخل المشروع

- وجود مستودع GitHub باسم `Solvanix/urban-sense-core`.
- وجود وثائق وخطط لنظام محتوى WordPress وصوت تحريري عربي.
- وجود نموذج بيانات موحد لبطاقات المحتوى.
- وجود مواد عن العيزرية والمسارات والسياحة المسؤولة.
- وجود مواصفة MABA تقنية مفصلة بحالة For review and approval.
- وجود عرض TIBYAN–SENSE–UrbanUP لبرنامج ابتكار بلدي.
- وجود صفحة Facebook فعلية لـ«أثر الحجر».
- وجود مسودة اختبار تطوير محتوى ونسخة مملوءة ومحسنة إبداعيًا.

### غير المثبت بعد

- نظام NFC عامل في الميدان.
- محفظة أو بوابة دفع أو تسويات مالية.
- عقد نهائي مع بلدية أو شركة باصات، إلا إذا أُضيفت وثيقة مستقلة.
- إيرادات أو عملاء مدفوعون للمنصة السياحية.
- توفر حجز أو سعر أو موعد لأي مسار.
- فتح المغارة أو صلاحيتها للزيارة.
- حقوق كل الصور أو التسجيلات أو شهادات الأشخاص.
- صلاحية كل أرقام السوق والأثر الواردة في العرض.

يجب أن تظهر هذه الحدود في المحتوى والعروض. لا يجوز تحويل هدف أو تقدير أو اهتمام أولي إلى نتيجة محققة.

## 4. مصادر الحقيقة وترتيب الثقة

عند التعارض، يستخدم Manus هذا الترتيب:

1. قرار مكتوب حديث في GitHub.
2. وثيقة أو عقد أو مصدر أولي يرفقه المستخدم.
3. بيانات WordPress المراجعة مع تاريخ آخر تحديث.
4. مقابلة أو مراجعة ميدانية موثقة.
5. صفحة Facebook أو LinkedIn عامة.
6. مسودة أو فكرة أو عرض تقديمي غير مدعوم.
7. اقتراح إبداعي غير موصوف بأنه حقيقة.

كل مادة يجب أن تفرق بين: **مؤكد، قيد التحقق، مستهدف، مقترح، وغير متاح**.

## 5. المنتج الأول الذي يجب بناؤه

لا يبدأ المشروع بتطبيق NFC أو محفظة أو منصة بلدية متعددة المستأجرين. يبدأ بمنتج محتوى وتجربة صغير:

- مسار واحد.
- خمس إلى عشر محطات.
- قصص موثقة أو موسومة بوضوح كمسودة.
- صفحات WordPress.
- QR أو رابط قابل للمشاركة.
- تجربة هاتفية بسيطة.
- شركة باصات أو شريك تشغيل إذا توفرت الموافقة.
- شريك محلي واحد على الأقل.
- مؤشرات قياس واضحة.

## 7. خطة GitHub

### المرحلة 1: ترتيب المستودع

يجب الحفاظ على بنية واضحة:

- `docs/`: القرارات والخطط والمواصفات.
- `schemas/`: مخططات بيانات المحتوى.
- `content/stories/`: النصوص وبطاقات JSON.
- `docs/wordpress/`: نماذج WordPress وسير التحرير.
- `apps/`: التطبيقات والنماذج البرمجية.
- `research/`: الأبحاث والافتراضات مع وسمها.

يجب عدم رفع كلمات المرور أو رموز WordPress أو بيانات شخصية غير لازمة. لا يرفع ملف الاختبار الشخصي نفسه إلى مستودع عام؛ يرفع فقط خطة المنهج أو نسخة منزوعة البيانات إذا لزم.

### المرحلة 2: بطاقة كل مادة

كل قصة أو منتج أو مسار يُسجل في بطاقة تطابق `schemas/sense-content-card.schema.json`. الحقول الأساسية:

- `id`
- `type`
- `title`
- `hook`
- `place`
- `question`
- `humanDetail`
- `facts`
- `unknowns`
- `source`
- `rights`
- `access`
- `nextAction`
- `cta`
- `status`
- `lastReviewed`
- `wordpress`
- `social`

الحالات: `draft`، `needs_review`، `verified`، `published`، `archived`.

### المرحلة 3: سير Pull Request

1. فتح Issue بسؤال واضح.
2. إنشاء بطاقة محتوى.
3. فصل الحقائق عن اللغة الأدبية.
4. إضافة المصادر والحقوق.
5. كتابة القصة.
6. فحص الخصوصية والوصول.
7. إضافة مشتقات Social.
8. فتح Pull Request.
9. مراجعة بشرية.
10. الدمج.
11. نقل النص إلى WordPress كمسودة.

لا تنتقل المادة إلى `verified` لأن النص جميل؛ تنتقل فقط بعد مراجعة الدليل والوصول والحقوق.

## 8. خطة WordPress

### المرحلة الأولى: الصفحات الأساسية

يبني Manus الصفحات التالية كمسودات:

1. الصفحة الرئيسية لـSENSE.
2. صفحة «اكتشف العيزرية».
3. صفحة SENSE Routes.
4. صفحة قصة المكان الأولى.
5. صفحة سهولة الوصول والقيود.
6. صفحة المصادر والحقوق.
7. صفحة عن SENSE وحدود المشروع.
8. صفحة تواصل.

### مبدأ النشر

WordPress هو طبقة المحتوى العام، وليس مصدر الحقيقة للكود أو العقود. كل صفحة تعرض حالة المادة وتاريخ آخر تحديث عند الحاجة. لا تستخدم أزرار «احجز الآن» أو «اشترِ الآن» إذا لم تكن آلية الحجز أو الطلب عاملة.

### القصة الأولى

القصة الأولى هي:

> **من الزيتونة إلى المغارة: رحلة لا تستهلك المكان**

حالتها الحالية `needs_review`. لا تُعرض المغارة كنقطة مفتوحة، ولا تُذكر نقطة بداية أو سعر أو حجز قبل المراجعة المحلية.

### معايير WordPress

- عنوان واحد واضح.
- فقرات قصيرة.
- عناوين قابلة للقراءة الصوتية.
- صورة مرخصة مع نص بديل.
- مصدر وتاريخ مراجعة.
- حدود الوصول ظاهرة.
- CTA واحد.
- عدم نشر شهادات أو صور أشخاص دون موافقة.

## 9. خطة Facebook

### صفحة «أثر الحجر» الحالية

الرابط العام: `https://www.facebook.com/profile.php?id=61594686114575`

الصفحة تجارية/خدمية، ووصفها يذكر الحجر والجرانيت والبورسلان وCNC وCAD/CAM. لا يعيد Manus تعريفها بوصفها صفحة سياحية.

### محتوى صفحة أثر الحجر

- مشاريع حجرية منفذة.
- تفاصيل المواد والتصميم.
- قبل/بعد عند وجود موافقة.
- شرح CNC وCAD/CAM بلغة مبسطة.
- صور الورشة أو التنفيذ بعد التأكد من الحقوق.
- قصة مهنية منفصلة يمكن لـSENSE إعادة صياغتها بعد موافقة صاحب النشاط.

### محتوى SENSE على Facebook

- قصص المكان.
- مسارات وتجارب قيد التحقق.
- معلومات عملية.
- دعوات Pilot.
- قصص الحرفيين والشركاء.

لا يُنشر محتوى SENSE السياحي على صفحة أثر الحجر إلا إذا كان المنشور متعلقًا مباشرة بالحرفة أو المنتج أو القصة المشتركة.

### المنشور المثبت المقترح لـSENSE

> لا نمرّ بالمكان فقط. نتوقف عند الحجر والطريق وصوت الشخص الذي يعرف القصة. نشارك قصص الأماكن ومساراتها وتجارب أهلها والمنتجات التي تحمل أثرها، ونوضح ما نعرفه وما يحتاج إلى تحقق. نبدأ من المكان ونعود دائمًا إلى أهله. اكتشف المكان. عش القصة. خذ جزءًا منها معك.

### طريقة النشر

كل منشور له هدف واحد: قراءة قصة، فتح بطاقة مسار، إرسال سؤال، أو تسجيل اهتمام. لا تجمع الصفحة أربعة أزرار في منشور واحد.

## 10. خطة Instagram

Instagram قناة الصورة والتفصيل، وليست قناة الإثبات الوحيدة.

### الصيغ

- Carousel: مشهد، سياق، سؤال، حدود، CTA.
- Reel: 20–45 ثانية من مادة موثقة.
- Story: سؤال أو استطلاع أو خلف الكواليس.
- صورة منتج: صاحب المنتج، المادة، المكان، حالة التوفر.

كل صورة تحتاج مصدرًا وحقوقًا ونصًا بديلًا داخليًا حتى لو لم يظهر للمستخدم.

## 11. خطة X

تستخدم X للتحديثات القصيرة والتحقق وروابط القصص، لا لنشر ادعاءات كبيرة دون مصدر.

النمط:

```text
فكرة واحدة قوية + معلومة محددة + حد أو مصدر + CTA واحد
```

مثال موضوعي:

> ليست كل نقطة جميلة جاهزة للزيارة. نوضح ما نعرفه وما يحتاج إلى إذن أو تحقق. اقرأ القصة، ثم اسأل قبل الزيارة.

## 12. خطة LinkedIn

LinkedIn قناة الشراكات والبلديات والجهات التعليمية والمهنية.

### أنواع المنشورات

- ما الذي بُني فعلًا.
- ما الذي اختُبر.
- ماذا تعلمنا من Pilot.
- قصة حرفة مرتبطة بالتقنية.
- مؤشر أثر مع خط أساس وهدف.
- طلب اجتماع بلدي واضح.
- دراسة حالة لا تدعي نجاحًا غير مثبت.

لا تنشر LinkedIn أرقام العرض مثل 70% هامش أو 30% خفض انبعاثات بوصفها نتائج إلا بعد وجود نموذج أو قياس قابل للمراجعة.

## 13. القنوات الأخرى

### YouTube

يُستخدم للفيديو الأطول: قصة المكان، مقابلة بموافقة، شرح الحرفة، أو تقرير Pilot. يجب فصل الفيديو التوثيقي عن الفيديو الدعائي.

### TikTok

يُستخدم للمشهد القصير والشرح البصري، مع عدم اختزال المكان إلى ترند أو كشف خصوصية السكان.

### WhatsApp

يُستخدم للتواصل مع الشركاء أو المسجلين فقط بعد موافقة مناسبة. لا تُجمع أرقام الناس من التعليقات العامة دون إذن.

### Email

يُستخدم للشركاء والبلديات والمدارس والنشرات، مع قائمة موافقة وخيار إلغاء الاشتراك.

## 14. تحويل ملف الاختبار إلى نظام

ملف الاختبار لا يصبح مادة SENSE، لكنه يقدم المنهج:

- Hook من أول سطر.
- فكرة واحدة لكل قناة.
- تفصيل إنساني.
- توازن بين المعلومة والانفعال.
- CTA واضح.
- التزام بعدد الكلمات والحروف.
- التحقق قبل المشاركة.

يُطبق المنهج على كل قصة أو منتج أو منشور. موضوع الصيانة يُستخدم لتعلم عرض الخدمة والمهارة والأثر الاجتماعي، وموضوع المكتبة لتعلم الوصول إلى المعرفة، وموضوع الصور القديمة لتعلم التحقق من المصدر.

## 15. خطة 90 يومًا

### الأيام 1–7: التأسيس

يثبت Manus بنية العلامة، يراجع الملفات الحالية، يضع قائمة الحقائق والافتراضات، ويحول المواد الأولى إلى Issues وبطاقات محتوى. لا ينشر شيئًا عامًا في هذه الفترة.

### الأيام 8–21: المحتوى الأول

يُراجع نص الصفحة الرئيسية، ويُراجع نموذج القصة الأولى، وتُجهز بطاقة «من الزيتونة إلى المغارة»، وقصة حرفة منفصلة عن «أثر الحجر» بعد موافقة صاحب النشاط، وصفحة المصادر والحقوق.

### الأيام 22–35: WordPress وSocial

تُنقل القصص إلى WordPress كمسودات. تُجهز ثلاثة منشورات Facebook، وCarousel واحد، وثلاث رسائل X، ومنشور LinkedIn واحد. تُراجع الصور والروابط والـCTA.

### الأيام 36–60: Pilot

يُختار مسار واحد أو تجربة باص واحدة، ويُحدد الشريك والمالك التشغيلي ومؤشرات القياس. تُستخدم QR وروابط قابلة للتتبع. لا يعلن عن موعد أو حجز قبل تأكيد التشغيل.

### الأيام 61–75: القياس

تُقاس الزيارات، وفتح القصص، ومسح QR، والاستفسارات، والحضور، والملاحظات، ووضوح معلومات الوصول. تُسجل النتائج في GitHub مع الحدود.

### الأيام 76–90: القرار

يُكتب تقرير Pilot. القرار واحد من ثلاثة: الاستمرار، تعديل النطاق، أو إيقاف الفكرة. إذا ثبتت الحاجة إلى هوية رقمية أو خصومات، يُفتح مسار تقني مستقل لدراسة NFC المحدود.

## 16. ما لا يفعله Manus دون طلب أو دليل

- لا ينشر مباشرة على WordPress.
- لا يغير وصف صفحة Facebook التجارية إلى وصف سياحي.
- لا ينشئ حسابات اجتماعية جديدة دون قرار علامة.
- لا يعلن شراكة أو عقدًا أو خطاب نوايا غير موثق.
- لا يذكر أن MABA NFC منفذ.
- لا يعرض المغارة أو أي موقع حساس كنقطة زيارة مفتوحة.
- لا يضع سعرًا أو موعدًا أو حجزًا غير مؤكد.
- لا يستخدم صورة مولدة كصورة ميدانية.
- لا ينشر وجه شخص أو بيتًا خاصًا دون موافقة.
- لا يرفع كلمات مرور أو رموز API إلى GitHub.
- لا يخلط حقائق الاختبار مع حقائق SENSE.

## 17. معايير قبول كل مرحلة

لا تُغلق المرحلة إلا إذا توفر:

- ملف أو صفحة قابلة للفتح.
- حالة واضحة.
- مصدر أو وسم «غير متحقق».
- حقوق الوسائط.
- مراجع بشري عند الحاجة.
- CTA واحد.
- قياس أو طريقة قياس.
- سجل تغيير في GitHub.

## 19. معيار النجاح النهائي

ينجح المشروع الأول عندما يستطيع زائر حقيقي أن يقرأ قصة، ويفهم مكانها وحدودها، ويفتح بطاقة مسار، ويعرف ما الذي يمكنه فعله وما الذي يحتاج إلى سؤال أو إذن، بينما يستطيع شريك محلي أن يرى كيف تصل المنفعة إليه. عندها فقط يصبح من المنطقي توسيع المحتوى إلى باص وكتالوج وشراكات، ثم دراسة NFC أو نظام بلدي أوسع.
