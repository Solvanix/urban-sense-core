# تدقيق مشروع Pizza Hot عبر مستودعات GitHub

**تاريخ التدقيق:** 20 أكتوبر 2026

## النتيجة التنفيذية

يوجد مساران مرتبطان ببيتزا هوت:

- المستودع القديم `Solvanix/pizza_hot`، وهو مشروع HTML كبير يحتوي صفحات ونسخًا احتياطية وأصولًا قديمة، وآخر دفع ظاهر له في 14 يوليو 2025.
- النسخة الأحدث داخل المستودع المركزي `Solvanix/urban-sense-core/apps/pizza-hot`، وهي نسخة ثابتة مستقلة بكتالوج JSON وسلة محلية ومساعد مقيد بالبيانات.

القرار: **يستمر التطوير في `urban-sense-core/apps/pizza-hot`، ولا يُدمج مشروع المطعم داخل تطبيق SENSE السياحي أو Urban-Sense المدني.** يبقى `Solvanix/pizza_hot` أرشيفًا ومرجعًا بصريًا إلى أن يُتخذ قرار مستقل بترحيله أو أرشفته.

## مقارنة المستودعات

| المستودع | طبيعته | صلته بتطبيق منيو/سلة/طلبات | القرار |
|---|---|---:|---|
| `urban-sense-core` | مستودع المنظومة المركزي، ويحتوي تطبيقًا مستقلًا في `apps/pizza-hot` | عالية | المصدر canonical لتطوير نسخة المطعم المستقلة |
| `urban_symbolic_city` | مشروع حضري واسع، وفيه نسخة SENSE قديمة بمكونات سلة وطلبات وإدارة | متوسطة تقنيًا، لكنها ليست مصدر Pizza Hot | لا نستخدمه كمصدر المنتج |
| `sense-hub` | تطبيق TypeScript/React فيه Cart وCommerce، لكنه سياق SENSE الداخلي | متوسطة تقنيًا | نستفيد من الأنماط فقط، ولا نخلط قواعد البيانات |
| `pizza_hot` | مشروع HTML قديم بمخرجات ونسخ احتياطية كثيرة | عالية بصريًا، منخفضة كمرجع صيانة | أرشيف لا يُبنى عليه دون تنظيف وترحيل مقصود |
| `sense-experience-platform` | مستودع تعريفي لا يحتوي تطبيقًا فعليًا؛ README فقط | ضعيفة | لا يصلح لتطبيق المطعم |
| `Data_Core` | مستودع تحليلات وملفات HTML/Jupyter متعددة | ضعيفة | لا علاقة تشغيلية مباشرة بالمنيو أو الطلبات |

## ما تم إصلاحه في النسخة المركزية

1. إضافة فلاتر تصنيف للمنيو، مثل «الكل» والتصنيفات القادمة من الكتالوج.
2. تشفير HTML للنصوص التي يعرضها المساعد والكتالوج داخل الواجهة، وتقليل مخاطر حقن محتوى غير موثوق.
3. منع إضافة صنف غير مسعّر إلى السلة على مستوى منطق الإضافة، وليس الزر فقط.
4. إضافة `type="button"` و`aria-label` لأزرار السلة، وتحسين تسميات حقول الاسم والهاتف والمنطقة.
5. تصحيح وثيقة المقارنة التي كانت تقول إن نسخة GitHub لم تُرفع، مع أنها موجودة داخل المستودع المركزي.

## ما لم ندّعِ إصلاحه

هذه النسخة ما زالت **نموذجًا ثابتًا**. لا تنفذ طلبًا حقيقيًا، ولا ترسل WhatsApp، ولا تخزن الطلبات على خادم، ولا تتصل ببوابة دفع أو نظام توصيل. كما أن العنوان والهاتف وساعات العمل ومناطق التوصيل والمكونات والحساسيات والمخزون تحتاج اعتمادًا مستقلًا من المزود.

لا يجوز نقل أسرار Stunning أو ملفات `.env.local` أو مفاتيح Convex إلى GitHub. أي لوحة إدارة أو بيانات عملاء يجب أن تكون ضمن خدمة خلفية محمية ومصادقة، لا ضمن صفحة GitHub Pages عامة.

## الخطوة التالية المقترحة

قبل إضافة Backend، يجب اعتماد الكتالوج من المزود، ثم إنشاء خدمة طلبات مستقلة ذات مصادقة وصلاحيات وسجل تدقيق وسياسة خصوصية. بعد ذلك فقط يمكن ربط زر «إرسال للمراجعة» بطلب محفوظ فعليًا. الدفع والتوصيل يظلان مرحلة لاحقة بعد تحديد الجهة المشغلة ومصدر الحقيقة للطلبات.
