# مواصفة الإطار الإخباري والدلتا الحية

## القرار

تعمل SENSE بثلاث طبقات لا بطبقة واحدة:

1. **سجل الوجهة:** معلومات بطيئة التغير عن المكان والذاكرة وأصحاب التجارب والمنتجات.
2. **سجل التجربة:** ما يمكن للزائر فعله، ومن يقدمه، وما يحتاج موافقة أو اختبارًا.
3. **سجل الدلتا الحية:** ما تغيّر مؤخرًا في الوصول أو الفعالية أو التوفر أو السلامة أو حالة التشغيل.

الإطار الإخباري هو بوابة التحرير التي تقرر كيف يتحول السجلان الثاني والثالث إلى خبر أو تحديث أو تقرير أو قصة أو تنبيه محدود.

## لماذا نحتاج الفصل؟

القصة لا تنتهي صلاحيتها بسرعة، لكن موعد الفعالية قد يتغير. وصف الحرفة يمكن أن يبقى، لكن السعر أو التوفر يحتاج تحديثًا. مكان الزيارة قد يكون معروفًا، لكن الوصول إليه قد يتأثر بإغلاق أو ظرف ميداني. إذا خلطنا هذه الأنواع، يظهر المحتوى القديم كأنه وعد حي، أو يظهر البلاغ المؤقت كأنه حقيقة دائمة.

## بطاقة الدلتا

```json
{
  "deltaId": "delta-unique-id",
  "entityId": "experience-or-place-id",
  "field": "accessStatus",
  "previousValue": "needs_review",
  "newValue": "temporarily_unavailable",
  "observedAt": "YYYY-MM-DDThh:mm:ssZ",
  "source": {"kind": "field_review", "label": "وصف المصدر"},
  "confidence": "medium",
  "validUntil": "YYYY-MM-DDThh:mm:ssZ",
  "publicSummary": "الحالة تحتاج تأكيدًا قبل الزيارة.",
  "reviewStatus": "needs_review",
  "lastReviewedBy": "role-not-personal-data"
}
```

لا تُملأ قيمة أو وقت أو مصدر من الخيال. إذا لم توجد قيمة سابقة، نكتب `unknown` بدل اختراع baseline. إذا لم نعرف مدة الصلاحية، لا نعرض الدلتا كتنبيه حي.

## أنواع الدلتا المناسبة للعيزرية

| النوع | مثال | الصيغة العامة |
|---|---|---|
| الوصول | طريق أو نقطة تحتاج تحققًا | «آخر رصد… ويحتاج تأكيدًا» |
| الفعالية | موعد أو مكان أو سعة تغير | «تحديث فعالية بتاريخ…» |
| التجربة | مضيف أو ورشة غير جاهزة | «قيد التجهيز/بانتظار الموافقة» |
| المتجر | منتج متوفر أو متوقف | «التوفر يحتاج تأكيدًا من صاحب المنتج» |
| المجتمع | طلب إزالة أو حماية أو خصوصية | لا ينشر تفصيلًا حساسًا؛ يسجل قرارًا داخليًا |
| الخبر المحلي | قرار أو حادثة أو تصحيح | ينشر وفق بطاقة الادعاء والمصدر |

## دورة الخبر

تبدأ المادة بملاحظة أو بلاغ. يفككها المحرر إلى ادعاء واحد أو أكثر. ثم يحفظ المصدر والوقت والمنطقة العامة، ويبحث عن مصدر أولي أو مستقل عند الحاجة. بعد ذلك يحدد الحالة: مؤكد، مرجح، قيد التحقق، متعارض، غير صحيح، أو منتهي الصلاحية. لا يُنشر المحتوى الحساس من شخص واحد في دورة واحدة إذا كان يحتاج مراجعة ثانية.

بعد النشر، تُراقب الدلتا. إذا تغيرت الحقيقة، نحدّث المادة ونربط التصحيح بالأصل. لا نمحو أثر التغيير؛ نوضح للقارئ أن الحالة تغيرت ومتى ولماذا.

## كيف تخدم السياحة والمتجر؟

عند وجود قصة عن مضيف أو منتج، يبقى المقال في WordPress طبقة سياق. أما التوفر والسعر ووقت الاستقبال ووسيلة الطلب فتأتي من بطاقة تشغيل منفصلة. يستطيع القارئ قراءة القصة حتى عندما يتوقف المنتج، لكن لا يرى زر شراء أو حجزًا ما لم تكن القيمة التشغيلية محدثة ومالكها معلومًا.

وعند وجود فعالية، تنشر القصة قبل الحدث، وتُدار الدلتا أثناء التغيير، ثم يتحول ما حدث إلى تقرير بعد الحدث. هكذا لا نستخدم خبرًا قديمًا لتسويق موعد جديد، ولا نضيع الدروس التشغيلية بعد انتهاء الفعالية.

## ما يظهر للعامة

يظهر ملخص واضح، المنطقة العامة، وقت آخر رصد، حالة التحقق، فترة الصلاحية إن وجدت، ورابط المصدر العام عندما يكون نشره مشروعًا. لا تظهر هوية المبلّغ أو رقم هاتفه أو عنوانه الدقيق أو ملاحظات التقييم الداخلية.

## مؤشرات نجاح الطبقة

نجاح الدلتا لا يقاس بعدد التنبيهات. نقيس نسبة المواد التي تحمل وقتًا ومصدرًا، عدد التحديثات التي انتهت صلاحيتها دون أن تتحول إلى معلومة قديمة، زمن تصحيح الخطأ، قدرة القارئ على التمييز بين القصة والحالة المؤقتة، وعدد المرات التي منعت فيها المراجعة وعدًا غير صحيح.

## حدود التنفيذ

لا نعلن «بيانات حية» قبل وجود مصدر تشغيلي، وتواتر تحديث، ومالك، ومسار فشل. البداية اليدوية مقبولة: نموذج استقبال، سجل GitHub، مراجع، ومسودة WordPress. يمكن إضافة API أو MQTT أو لوحة مباشرة بعد إثبات أن الدورة اليدوية تُستخدم وتقدم قيمة.
