# نموذج أعمال Solvanix العميق

## الفكرة المركزية

Solvanix ليست مجموعة مستودعات متفرقة، وليست وكالة تنفذ مواقع بلا ذاكرة. هي **استوديو منظومات** يحوّل المعرفة المحلية والمشاريع التعليمية والبيانات والواجهات إلى منتجات موثوقة قابلة للتشغيل.

النواة التجارية ليست بيع تطبيق واحد. النواة هي **طبقة الثقة والتحويل**:

```text
أثر أو مشكلة محلية
  → معرفة منظمة ومصدر واضح
  → بطاقة قابلة للمراجعة
  → تجربة أو أداة قابلة للاستخدام
  → شريك أو مؤسسة تدفع مقابل التشغيل
  → أثر يمكن قياسه وإعادة استخدامه
```

كل فرع يبيع قيمة مختلفة، لكنه يعود إلى نفس أصول النواة: سجل الأدلة، العقود، المراجعة البشرية، أدوات الوصول، وقاعدة عدم خلط التجريبي بالخدمة المؤكدة.

## خريطة الفروع

### 1. SENSE Core — طبقة الثقة والحوكمة

**العميل:** بلدية، مؤسسة أهلية، جهة تعليمية، أو مشغل منظومة.

**القيمة:** تحويل البلاغات والادعاءات والمصادر والقرارات إلى سجلات قابلة للمراجعة بدل ملفات متناثرة أو محتوى دعائي.

**ما يباع:** إعداد النواة، عقود البيانات، لوحة المراجعة، سياسات الصلاحيات، والتدريب.

**نموذج الإيراد الأول:** مشروع تأسيس مدفوع، ثم اشتراك تشغيل وصيانة مؤسسي.

### 2. SENSE Experience — طبقة التجربة المحلية الشاملة

**العميل:** مزود تجربة، بلدية سياحية، جمعية محلية، أو برنامج وجهة.

**القيمة:** بطاقة تجربة عربية تقول للزائر ما يعرفه النظام وما لم يتحقق منه، وتمنع ادعاء الحجز أو الإتاحة قبل وجود مصدر تشغيلي.

**ما يباع:** برنامج وجهة تجريبي، تفعيل مزودين، مراجعة محتوى، وتحسين تجربة ما قبل الزيارة.

**نموذج الإيراد الأول:** رسوم تفعيل الوجهة والمحتوى؛ لا نبدأ بعمولة حجز قبل وجود مصدر حقيقة وتشغيل قانوني واضح.

### 3. SENSE Civic — طبقة المدينة والبلاغ المدني

**العميل:** بلدية أو جهة مدنية.

**القيمة:** استقبال البلاغ، حفظ المصدر والوقت، توجيه الحالة، وإظهار ما تم وما لم يتم دون كشف بيانات حساسة.

**ما يباع:** نسخة مؤسسية محدودة النطاق مع إعداد الصلاحيات وسجل التدقيق وتقرير أثر شهري.

**نموذج الإيراد الأول:** عقد خدمة مؤسسي؛ لا تُربط إيراداتها مباشرة بالبيانات الشخصية أو بيع البلاغات.

### 4. STEAM Forge — طبقة التعلم والتحويل

**العميل:** مدرسة، جامعة، برنامج شباب، أو جهة مانحة.

**القيمة:** تحويل مشروع الطالب أو التجربة التقنية إلى منتج قابل للعرض والاختبار، مع ملف إنجاز ومراجعة لا مجرد مستودع مهجور.

**ما يباع:** مختبرات قصيرة، مراجعة مشاريع، مسارات بناء، ومعرض رقمي للنتائج.

**نموذج الإيراد الأول:** رسوم برامج، رعاية مختبر، وحزم تدريب؛ مع فصل واضح بين التعليم وبيانات المشاركين.

### 5. SENSE Commerce — طبقة المنتج والقصة

**العميل:** متجر محلي، حرفي، مطعم، أو مزود منتج.

**القيمة:** ربط المنتج بقصة ومصدر وحدود نشر، ثم تحسين صفحة البيع دون تحويل الادعاءات إلى شارات تلقائية.

**ما يباع:** حزمة هوية/محتوى/واجهة، تفعيل كتالوج، وتحسين التحويل.

**نموذج الإيراد الأول:** تنفيذ وحزمة شهرية للمحتوى؛ عمولة المعاملات تؤجل إلى حين اعتماد الدفع، الاسترداد، الضرائب، ومصدر الحقيقة.

### 6. Media & Evidence Studio — طبقة المحتوى والدليل

**العميل:** مشروع تخرج، مؤسسة، جهة إعلامية، أو شريك يريد قصة مسؤولة.

**القيمة:** إنتاج قصة متعددة الوسائط مرتبطة بمصادر وحقوق نشر وحالة تحقق، لا فيديو جميل منفصل عن المنتج.

**ما يباع:** بحث، سيناريو، صور/صوت/فيديو، حزمة نشر، وسجل أصول.

**نموذج الإيراد الأول:** رسوم إنتاج ونطاق عمل مكتوب؛ الملكية والترخيص والتعديلات تحدد قبل التنفيذ.

## كيف ترتبط الفروع دون فوضى؟

هناك أربعة أصول مشتركة فقط تنتقل بين الفروع:

1. **هوية العقدة:** من هو الشريك أو المكان أو المشروع؟
2. **سجل الدليل:** ما المصدر، وما تاريخه، وما درجة الثقة؟
3. **عقد النشر:** ما الذي يجوز عرضه ولمن ومتى؟
4. **سجل الأثر:** ما الذي تغير بعد إطلاق المنتج؟

إذا لم يقدم الفرع أصلًا واحدًا من هذه الأصول أو لا يستفيد منها، يبقى مشروعًا تجريبيًا أو أرشيفًا، ولا ينشئ قاعدة تشغيل جديدة.

## مسارات البيع

### المسار المؤسسي

```text
تشخيص مدفوع
  → خريطة مصادر وصلاحيات
  → تجربة محدودة لوجهة أو وحدة
  → عقد تشغيل
  → توسعة إلى بلاغات/تجارب/تعلم
```

### مسار الشريك المحلي

```text
محادثة تعريفية
  → بطاقة خاصة
  → مراجعة ادعاء أو مصدر
  → بطاقة عامة محدودة
  → تحسين محتوى أو طلب تواصل
```

### مسار التعليم

```text
مشروع طالب
  → عقد بيانات وحقوق
  → مراجعة تقنية ومحتوى
  → معرض أو تجربة صغيرة
  → تحويل الاختبار الناجح إلى منتج مؤسسي
```

## ترتيب الأولويات التجارية

### المرحلة الأولى: إثبات النواة

- جعل `urban-sense-core` المرجع التشغيلي الوحيد.
- تثبيت سجل الادعاءات والأدلة والمراجعة.
- بيع حزمة تأسيس صغيرة لجهة واحدة أو وجهة واحدة.
- إبقاء `Product_Store` و`pizza_hot` كحالات استخدام، لا كأنظمة مالية مستقلة.

### المرحلة الثانية: تكرار التجربة

- تحويل تجربة العيزرية إلى قالب قابل لإعادة الاستخدام.
- إضافة كيان منطقة مستقل قبل توسيع فلسطين.
- إصدار تقارير أثر شهرية: عدد البطاقات، الأدلة المراجعة، الحالات المعلقة، وملاحظات الوصول.
- بناء مسار STEAM يحول المشاريع التعليمية إلى أصول معرفة قابلة لإعادة الاستخدام.

### المرحلة الثالثة: إيراد متشعب مضبوط

- اشتراك مؤسسي للنواة.
- رسوم تفعيل ومراجعة للتجارب.
- حزم إنتاج للمحتوى.
- برامج تعليمية ورعاية مختبرات.
- خدمات تجارة فقط بعد اعتماد طبقة الدفع والاسترداد والسياسة القانونية.

## بوابات تمنع الانحراف

- لا نعرض حسابًا قديمًا أو مستودعًا خارجيًا على أنه مملوك حتى يثبت ذلك.
- لا نحول تجربة أو ادعاء وصول إلى اعتماد عام دون اختبار تشاركي ومصدر.
- لا نربط الدفع أو الحجز قبل وجود مشغل ومصدر حقيقة وسياسة استرداد.
- لا نخلط بيانات التعليم أو البلاغات أو الشركاء في سجل عام واحد.
- لا نبني مستودعًا جديدًا عندما يكفي عقد أو صفحة أو وحدة داخل النواة.
- لا نستخدم لغة «منصة وطنية» قبل وجود شريك تشغيل ونطاق جغرافي ومسؤولية واضحة.

## مؤشرات صحة النموذج

- نسبة الادعاءات التي لها مصدر وحالة مراجعة.
- الزمن من إدخال الشريك إلى أول بطاقة قابلة للنشر.
- نسبة البطاقات التي لم تسبب مفاجأة تشغيلية للزائر.
- عدد الوحدات التي أعيد استخدامها بين فرعين دون نسخ البيانات.
- إيراد كل فرع مقابل تكلفة دعمه.
- عدد المشاريع المؤرشفة أو المدمجة بدل استمرار التكرار.
- حالات الوصول التي اختبرها مستخدمون حقيقيون، لا ما ادعاه المصمم.

## القرار التنفيذي

المشروع العميق ليس ربط كل شيء بكل شيء. القرار هو بناء **نواة واحدة، ستة فروع تجارية، وأربعة أصول مشتركة**. كل حساب قديم يدخل كذاكرة أو مصدر محتمل، وكل مستودع يدخل ببطاقة وحدود، وكل فرع يثبت قيمته عبر عميل أو شريك أو أثر قابل للقياس.

بهذا تصبح Solvanix منظومة تشعبية لكن منظمة: يمكن أن تبدأ من مشروع طلابي، تمر عبر دليل ومراجعة، تتحول إلى تجربة أو أداة مدنية، وتنتهي بعقد مؤسسي أو منتج محلي—من دون فقدان المصدر أو السيطرة على الحدود.
