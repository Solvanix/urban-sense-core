# عقد هوية مراجع SENSE Experience

## مبدأ الفصل

هوية المراجع في SENSE Experience مورد داخلي منفصل. لا تقبل الخدمة قيمة دور من واجهة المتصفح أو ترويسة يرسلها العميل، ولا تستورد جدول المستخدمين أو ملفات الجلسات أو أدوار Urban‑Sense. أي ربط بمزود OAuth مستقبلي ينشئ أو يطابق سجل هوية خاصًا بهذا التطبيق فقط.

## نموذج البيانات

| الجدول | الغرض | الوصول |
|---|---|---|
| `sx_reviewer_identity` | ربط موضوع خارجي موثق (`provider` + `subject`) بمعرف داخلي وحالة تفعيل. | مدير مصرح فقط. |
| `sx_reviewer_role_assignment` | منح أو سحب دور `reviewer` أو `administrator` مع من أصدر القرار وسببه ووقته. | مدير مصرح فقط. |
| `sx_audit_event` | تسجيل تعيين أو سحب دور وهوية من نفذه. | مراجع مخول أو مدير وفق سياسة التشغيل. |

## التسلسل

```text
مزود هوية موثق
  → محول هوية على الخادم يتحقق من الجلسة أو الرمز
  → sx_reviewer_identity (حالة active)
  → sx_reviewer_role_assignment (غير مسحوب)
  → ReviewerActor داخل سياق tRPC
  → قرار مراجعة مسبب ومسجل
```

لا يبدأ التسلسل من اسم أو بريد واردين من الطلب، ولا من معرّف مخزن في المتصفح، ولا من ترويسة دور. قبل إعداد مزود OAuth المستقل، يستخدم الخادم محلل هوية رافضًا افتراضيًا؛ لذلك تظل مسارات المراجع مغلقة حتى لو كان API مفعلًا.

## بوابة التشغيل

لا يضاف مزود OAuth أو متغيراته أو نطاقات إعادة التوجيه إلى بيئة التشغيل إلا بعد إنشاء تطبيق هوية مستقل لـSENSE Experience. عند إنشاء الدعوات أو إعادة التوجيه، يمرر العميل `window.location.origin` ويقيّد الخادم العودة بمسار داخلي ثابت، مع nonce مرتبط بالمتصفح، وفق إرشادات OAuth. [1]
