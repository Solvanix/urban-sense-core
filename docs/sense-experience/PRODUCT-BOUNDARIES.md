# SENSE Experience — حدود المنتج داخل المستودع المركزي

## القرار

يستضيف مستودع `urban-sense-core` أكثر من تطبيق مستقل تحت حوكمة واحدة. تطبيق `apps/web` هو Urban‑Sense للبلاغات البلدية. ويُضاف تطبيق `apps/sense-experience` لمنصة سياحية عربية للمزودين والزوار. لا تعني وحدة المستودع وحدة المنتج أو قاعدة البيانات.

| التطبيق | مسؤوليته | بياناته وصلاحياته |
|---|---|---|
| Urban‑Sense | بلاغات مدنية، دورة معالجة، دليل ميداني، سجل تدقيق. | قاعدة بيانات وOAuth وأدوار خاصة بالبلديات. |
| SENSE Experience | ملفات مزودين، خدمات وتجارب، مراجعة نشر، ودليل عام. | قاعدة بيانات ومستخدمون ومراجعون خاصون به. |
| SENSE Commerce، عند اعتماده لاحقًا | كتالوج وسلة وطلبات وتكامل دفع ولوجستيات. | قاعدة وبيانات دفع وطلبات مستقلة، مع عقود نشر ضيقة فقط. |

## قواعد لا تقبل الاستثناء

1. لا تقرأ منصة السياحة بلاغات Urban‑Sense أو مرفقاته أو مستخدميه، ولا العكس.
2. لا ينشأ مزود أو خدمة أو تقييم أو ادعاء وصول أو سعر افتراضي لتعبئة الواجهة.
3. لا تُنشر بيانات اتصال المزود أو ملفه العام قبل موافقته ومراجعة بشرية.
4. لا يعرض التطبيق السياحي حجزًا أو دفعًا أو توافرًا حيًا قبل وجود تكامل حقيقي ومعتمد.
5. تبنى العلاقات بين التطبيقات بعقود API موثقة ومعرفات عامة مصغرة، لا بجداول أو أسرار مشتركة.

## بنية المستودع المستهدفة

```text
apps/
  web/                  # Urban‑Sense civic reporting
  sense-experience/     # Arabic tourism provider and discovery application
docs/
  sense-experience/     # product and operational documentation
  decision-records/     # cross-application decisions
```
