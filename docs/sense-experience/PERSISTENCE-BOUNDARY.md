# حدود حفظ بيانات SENSE Experience

## الغرض

تحتاج تجربة الدعوة إلى حفظ طلب اهتمام ومراجعته، لكن هذا لا يبرر ربطها بقاعدة Urban‑Sense أو استخدامها لحفظ بيانات مزودين حقيقيين قبل اكتمال الحماية والمراجعة.

## السجلات المستقلة

| السجل | الغرض | ظاهر للعامة؟ |
|---|---|---|
| `provider_interest` | اسم العلامة، نوع الخدمة، المنطقة، وسيلة اتصال خاصة، وصف قصير، وموافقة المراجعة. | لا. |
| `interest_review_decision` | هوية المراجع، القرار، السبب، والوقت. | لا. |
| `provider_application` | ملف تفصيلي ينشأ فقط بعد دعوة صريحة للانضمام. | لا، حتى قبول النشر والتحقق. |
| `public_provider_profile` | إسقاط محدود للملف المعتمد والادعاءات المتحققة فقط. | نعم، في مرحلة لاحقة فقط. |

## حدود التنفيذ الحالي

التنفيذ الأول داخل `apps/sense-experience` يستخدم مخزن متصفح محليًا بغرض فحص تجربة الإدخال والمراجعة في جهاز واحد. ليس خادمًا، وليس قاعدة بيانات، ولا يسمح بتجربة مزودين حقيقيين أو مشاركة سجلات بين مستخدمين. يجب أن تعرض الواجهة هذا الحد بوضوح.

## بوابة الترقية إلى تخزين تشغيلي

قبل استقبال أي طلب حقيقي، يجب إضافة خدمة مستقلة وقاعدة بيانات منفصلة وترحيلات قابلة للمراجعة، وتسجيل دخول لأدوار المزود والمراجع، وتشفير أو ضوابط وصول لبيانات الاتصال، وسجل قرار غير قابل للتعديل، وسياسة احتفاظ/حذف وموافقة واضحة. لا تستخدم مفاتيح أو جداول أو مستخدمين أو أسرار Urban‑Sense في هذه الخطوة.
