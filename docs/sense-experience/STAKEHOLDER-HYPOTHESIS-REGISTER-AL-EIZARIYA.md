# سجل فرضيات أصحاب المصلحة — SENSE العيزرية

> **الغرض:** تحويل فكرة المنصة السياحية إلى فرضيات قابلة للاختبار مع البلديات والجهات الرسمية وأصحاب التجارب والسكان والزوار. هذا السجل لا يثبت وجود شراكة، ولا يمثل موافقة أي جهة، ولا يعلن خدمة حجز أو زيارة قبل اكتمال الدليل.

## الخلاصة التنفيذية

يمكن العمل على GitHub في ثلاث طبقات مترابطة. الطبقة الأولى هي **سجل الادعاءات والمصادر**؛ وهي توضح ما نعرفه عن المكان وما يحتاج تحققًا. الطبقة الثانية هي **تجارب صغيرة قابلة للقياس**؛ مثل اختبار بطاقة مسار مع عدد محدود من الزوار أو مقابلة مضيفين محليين. الطبقة الثالثة هي **حزم شراكة**؛ وهي مخرجات قصيرة مخصصة للبلدية أو الجهة السياحية أو صاحب المشروع، ولا تُرسل بوصفها اتفاقًا قبل موافقة صاحبها.

المبدأ الحاكم هو الفصل بين أربع حالات: **فرضية**، و**دليل**، و**تجربة**، و**قرار تشغيل**. لا تتحول الفرضية إلى وصف منشور لمجرد أنها تبدو منطقية، ولا يتحول اهتمام جهة ما إلى تعاون رسمي قبل وجود اسم جهة موافق ونطاق ومالك قرار.

| الإعلام وWordPress | قد تحتاج القصة إلى نسخة تحريرية قابلة للمراجعة بدل إعلان ترويجي. | مصدر القصة، الصورة، موافقة الاقتباس، والفرق بين الرواية والواقعة. | تحويل جواز الرحلة إلى مقال بمربعات “نعرف / نتحقق / لا نعد”. | مراجعة بشرية قبل النشر وتصحيح واضح عند تغير الحالة. | لا نفترض أن المقال إعلان حجز أو تمثيل رسمي. |
| الممولون أو برامج الابتكار | قد يدعمون بناء طبقة توثيق وتجربة قبل تمويل التوسع. | المشكلة، المخرج، المقياس، المخاطر، واستدامة التشغيل. | صفحة مشروع تلخص الجاهزية والفجوات والنتائج المتوقعة. | طلب معلومات أو دعوة رسمية أو تجربة ممولة بنطاق محدد. | لا نفترض أهلية تمويل أو قبولًا أو شراكة. |

## تسلسل العمل على GitHub

### 1. توثيق الادعاء

ينشئ الفريق ملفًا لكل مسار يتضمن اسم الادعاء، مصدره، تاريخ التحقق، صاحب المعلومة، مستوى الخصوصية، وما إذا كان صالحًا للنشر العام. الملفات الموجودة في `tourism/` تعرض تجربة الواجهة، لكنها لا تكفي وحدها لإثبات معلومات ميدانية.

### 2. تحويل الادعاء إلى تجربة صغيرة

كل فرضية يجب أن تتحول إلى تجربة لا تتطلب اتفاقًا كبيرًا. مثال ذلك: اختبار بطاقة “حين تتكلم الحجارة” مع خمسة زوار، أو مقابلة مضيفين اثنين حول السعة والوقت، أو فحص وصول واحد بمشاركة شخص يستخدم وسيلة مساعدة. يسجل GitHub السؤال والطريقة والنتيجة والقرار التالي، دون نشر بيانات شخصية.

### 3. إصدار حزمة جهة محددة

بعد ظهور دليل أولي، يخرج الفريق ملفًا قصيرًا بحسب الجهة. البلدية تحصل على بطاقة سلامة وملكية ومسؤوليات. الجهة السياحية تحصل على جواز جاهزية ومؤشرات وفجوات. المضيف يحصل على بطاقة عرض ومسودة حجز. WordPress يحصل على قصة محررة لا تتجاوز ما يثبته الدليل.

### 4. قرار الحالة

تستخدم كل بطاقة واحدة من الحالات التالية: **فرضية**، **تحتاج مصدرًا**، **قيد الاختبار**، **مراجعة بشرية**، **صالحة للعرض**، أو **موقوفة**. كلمة “مؤكد” لا تظهر إلا عندما يوجد دليل قابل للمراجعة ومالك معلوم للمعلومة.

## المقاييس الأولى

لا نبدأ بعدد الزيارات فقط. نبدأ بمقاييس تعلم تساعد على قرار مسؤول:

| المقياس | طريقة القياس | قرار محتمل |
|---|---|---|
| فهم الزائر للمسار | سؤال قصير بعد قراءة البطاقة | تعديل العنوان أو المدة أو حدود الوصول. |
| اكتمال ملف المضيف | نسبة الحقول التي لها مصدر أو إجابة واضحة | تحديد فجوة التدريب أو المقابلة التالية. |
| وضوح الحجز | قدرة الزائر على معرفة السعة والسعر وحالة التحقق | إبقاء المسودة أو فتح طلب تشغيلي بعد الشراكة. |
| احترام المكان | اعتراضات السكان أو ملاحظات المضيفين | تعديل نقطة التوقف أو إخفاء الموقع. |
| المنفعة المحلية | نوع المستفيد ومنفعة التجربة لا مجرد عدد الصور | تغيير النموذج أو إيقاف المسار. |
| قابلية الإحالة الرسمية | وجود جهة يمكنها مراجعة البطاقة | إعداد حزمة شراكة أو إبقاء المسار تحريريًا. |

## بوابة القرار

لا ينتقل المسار إلى “حجز” إلا إذا توفرت إجابات مؤرخة عن صاحب الخدمة، نقطة اللقاء، السعة، السعر أو طريقة تأكيده، سياسة الإلغاء، السلامة، ووسيلة التواصل. ولا ينتقل إلى “اعتماد رسمي” إلا بموافقة الجهة صاحبة الصلاحية. قبل ذلك، يظل زر المنصة **أنشئ مسودة طلب** لا **احجز الآن**.

## الخطوة التالية المقترحة

يبدأ الفريق بثلاث مقابلات قصيرة في العيزرية: مقابلة مع صاحب تجربة أو منتج محلي، ومقابلة مع شخص من المجتمع يعرف حدود المكان، ومقابلة مع جهة يمكنها مراجعة السلامة أو الوصول. لا نطلب منهم توقيع شراكة في اللقاء الأول. نطلب فقط تصحيح الفرضية وتحديد الدليل الذي ينقصها.

بعد المقابلات، تضاف النتائج إلى سجل GitHub في التزام مستقل. ثم تُحدّث بطاقة المسار ومقال WordPress مع بيان ما تغير ولماذا.
