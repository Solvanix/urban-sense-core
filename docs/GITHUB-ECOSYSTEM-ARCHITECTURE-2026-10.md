## قواعد الفصل

1. لا تُنقل كلمات مرور أو مفاتيح API أو ملفات بيئة من Stunning أو أي خدمة إلى GitHub.
2. لا تُحفظ بيانات العميل في صفحات عامة أو `localStorage` عند التشغيل الحقيقي.
3. لا تُعرض لوحة إدارة عامة بكلمة مرور JavaScript؛ المصادقة يجب أن تكون على الخادم.
4. لا يُعتبر الكتالوج أو السعر أو التوصيل معتمدًا لمجرد ظهوره في واجهة.
5. لا يُضاف Backend أو دفع قبل تحديد مالك البيانات والجهة المشغلة وسياسة الخصوصية.
6. تستخدم SENSE بياناتها وهوياتها وقواعدها المستقلة، ولا تقرأ طلبات Pizza Hot مباشرة.

## حالة الإصلاح الحالي

- تم تحديث `urban-sense-core/apps/pizza-hot` بفلاتر المنيو وتحسينات الوصول والحماية من إدراج HTML.
- تم توثيق مقارنة الحسابات والمستودعات في `docs/PIZZA-HOT-GITHUB-AUDIT-2026-10.md`.
- تم إيقاف `pizza-hot-ps/store/admin_orders.html` مؤقتًا وإزالة كلمة المرور الموجودة داخل الملف العام.
- أضيفت `pizza-hot-ps/store/SECURITY.md` كشرط قبل إعادة تفعيل الإدارة.

## بوابات الترقية إلى التشغيل

### G1 — اعتماد الكتالوج

يعتمد المزود الأسماء والأسعار والمكونات والحساسيات والمخزون ومناطق التوصيل وساعات العمل.

### G2 — Backend الطلبات

تُنقل الطلبات من التخزين المحلي إلى API وقاعدة بيانات، مع التحقق من المدخلات، سجل تدقيق، وسياسة احتفاظ.

### G3 — هوية الإدارة

تُضاف مصادقة خادمية، أدوار، جلسات آمنة، حماية من CSRF، ومنع الفهرسة، مع اختبارات وصول.

### G4 — التشغيل والخصوصية

تُعتمد سياسة الخصوصية، وموافقة العميل، وآلية حذف أو تصحيح البيانات، ومسؤول واضح عن الطلبات.

### G5 — الدفع والتوصيل

لا يُفعّل الدفع أو التوصيل إلا عبر شريك معتمد ومصدر حقيقة واضح للحالة والتسوية والاسترداد.

## القرار

تطوير واجهة العرض في `urban-sense-core`، وتطوير التشغيل التجاري في مؤسسة `pizza-hot-ps` بعد إغلاق بوابات الأمان والبيانات. لا ننشئ مستودعًا ثالثًا لنفس المنتج، ولا نستخدم المستودع الشخصي القديم كمصدر جديد.
