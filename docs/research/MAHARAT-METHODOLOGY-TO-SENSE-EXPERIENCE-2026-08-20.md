# من Maharat for Tourism إلى SENSE Experience: تحليل منهجي وتطبيق آمن

**الحالة:** تحليل منتج وتجربة مستخدم؛ لا يعني شراكة أو اعتمادًا أو نقل محتوى من SPARK أو Maharat.  
**حدود الوصول:** جرى فحص مساحة التعلم العامة فقط من الرابط الذي شاركه مالك المشروع. لم يُسجّل دخول، ولم تُفتح دورات مقيدة، ولم يُنسخ نص أو تمرين أو بيانات متعلم.

## ما ظهر وتحقق علنًا

تظهر صفحة **My learning space** العامة في Maharat عناصر تنقل مثل التسجيل وتسجيل الدخول والفعاليات والمنتديات. أما صفحات SPARK الرسمية فتصف برنامج Maharat for Tourism بوصفه مسارات تعلم رقمية متعددة، مع تسجيل وتهيئة ومجموعات تعلم محلية، وتؤكد وجود موضوعات مهارات رقمية وإدارة أعمال وخدمة عملاء وسياحة مستدامة.[1] [2] وتعرض SPARK أيضًا التعلّم المرن، والمناهج الموطّنة، وفرص التواصل، بينما يشير وصف البرنامج إلى متابعة التقدم والتفاعل عبر أدوات رقمية.[1] [3]

> لا يثبت ما سبق محتوى الوحدات المقيدة أو طريقة التقييم الداخلية أو ملكية SENSE لأي مادة. نستلهم **بنية التعلم والخدمة** فقط، لا الدورات أو الأمثلة أو العلامة أو القياس الخاص بـMaharat.

| طبقة منهجية مرئية أو معلنة | تفسير مناسب لـSENSE Experience | ما لا ننقله |
|---|---|---|
| تسجيل ثم مساحة تعلم | دخول يدعو المزود إلى «مسار جاهزية» بعد قبوله، لا قبل ذلك. | حسابات Maharat أو نموذج تسجيله أو بيانات المتعلمين. |
| مسارات متخصصة بحسب الجمهور | مسارات صغيرة منفصلة: مزود تجربة، مضيف/حرفة، مرشد محتوى، ومراجع جودة. | أسماء الدورات أو وحداتها التعليمية. |
| تعلم مرن وموطّن | إرشاد عربي بسيط قابل للتوقف والاستئناف، مع أمثلة يملكها SENSE أو يوافق عليها أصحابها. | محتوى أو ترجمة أو تصاميم البرنامج الأصلي. |
| مجموعة تعلم/مجتمع | جلسة مراجعة بشرية اختيارية أو قائمة أسئلة عامة بعد الموافقة. | منتديات Maharat أو شبكته أو هويات المشاركين. |
| متابعة تقدم | حالة جاهزية محدودة مثل «بدأ»، «أكمل ملفًا»، «جاهز لمراجعة بشرية». | تحليلات سلوكية أو بيانات حساسة بلا سياسة وموافقة. |

## العمق العملي الممكن الآن

يمكن لـSENSE Experience تطبيق المنهج على أربع طبقات، من دون أن يصبح منصة تعليم كاملة من اليوم الأول:

| الطبقة | التطبيق في SENSE Experience | حالة التنفيذ |
|---|---|---|
| **1. مسار الدور** | يختار المزود نوع مشاركته ثم يفهم ما الذي يحتاجه قبل عرض أي ملف عام. | يمكن تصميمه الآن؛ لا يقبل بيانات فعلية حتى تشغيل الخدمة المستقلة. |
| **2. بطاقات مهام قصيرة** | «عرّف تجربتك»، «حدد ما يمكن للزائر توقعه»، «أظهر موافقتك على التواصل»، «راجع السلامة والوصول». | هيكل قابل للبناء؛ المحتوى الأصلي يحتاج تحريرًا ومراجعة قطاعية. |
| **3. بوابة مراجعة بشرية** | لا تتحول المهمة المكتملة إلى نشر تلقائي؛ يراجع شخص مخوّل جودة الوصف وحدود الادعاء. | نواة الهوية والإسناد موجودة في الكود، لكنها غير منشورة ولا مهيأة بهويات حقيقية. |
| **4. أثر متناسب** | يقاس اكتمال الملف ومراجعة الجودة أولًا، ثم يضاف رضا اختياري أو بيانات أثر بموافقة. | مؤجل؛ لا لوحة أثر عامة ولا بيانات مزودين حقيقية. |

## رحلة مزود مقترحة: تعلم ثم إثبات ثم مراجعة

1. **دعوة أو اهتمام:** يقرأ المزود حدود التجربة، ولا يقدّم نفسه للعامة ولا يدفع رسومًا.
2. **اختيار مسار:** يختار فئة واضحة مثل تجربة محلية أو حرفة أو ضيافة؛ لا يستخدم النظام توصيفًا تلقائيًا مضللًا.
3. **مهام الاستعداد:** ينجز أربع بطاقات أصلية وقصيرة: تعريف العرض، توقع الزائر، شروط السلامة/الإتاحة، وموافقة الاتصال.
4. **مراجعة بشرية:** ينتقل الملف إلى مراجع مستقل ذي دور فعّال. يطلب المراجع إيضاحًا أو يقبل الملف للتجربة المحدودة أو يرفضه مع سبب.
5. **إطلاق تجريبي مقيد:** لا يتحول القبول إلى متجر أو حجز أو إعلان أثر؛ يبقى ضمن نطاق تجربة وموافقة لاحقة.

## ما لا يصح فعله الآن

لا يصح وصف هذا كـ«منهج Maharat داخل SENSE» أو الإيحاء بأن SPARK أو Google.org أو أي جهة مانحة تشارك في SENSE. ولا يصح إظهار نسبة إكمال، شهادات، شبكة مهنية، أو فرص عمل قبل وجود محتوى مملوك ووقت تعلم حقيقي وسياسة بيانات. كما لا يصح فتح تسجيل مزودين أو مسارات مراجعة عامة قبل نشر API مستقل وهوية OIDC ومراجع حقيقي وسجل احتفاظ معتمد.

## نموذج دخول المنظومة المقترح

البوابة الرئيسة لا تصبح لوحة تحكم واحدة. بل تشرح خمسة أبواب مستقلة:

| الدور | نقطة الدخول الصحيحة | ما يحتاجه | ما لا يحتاجه |
|---|---|---|---|
| زائر عام | بوابة SENSE وصفحات المنتجات العامة | لا حساب. | لا يرى إدارة أو بيانات أو قوائم مزودين. |
| بلدية/راعٍ تجريبي | Urban‑Sense ثم دعوة حساب مؤسسية عند تفعيل تجربة. | نطاق بلدي ودور داخل Urban‑Sense. | لا يحتاج GitHub أو حساب SENSE Experience. |
| مزود خدمة | مسار اهتمام/دعوة في SENSE Experience بعد النشر المستقل. | هوية مزود وموافقة واضحة. | لا يحصل على صلاحيات بلدية أو مستودع. |
| فريق SENSE التشغيلي | حساب منفصل لكل تطبيق ودور محدد. | أقل صلاحية لازمة وسجل تدقيق. | لا يصبح «مدير كل شيء» تلقائيًا. |
| فريق تقني | GitHub وفق أقل صلاحية: قراءة أو كتابة أو إدارة، مع مراجعة طلبات. | وصول مستودع فقط عند الحاجة. | لا يحصل تلقائيًا على بيانات إنتاج أو صلاحيات تطبيق. |
