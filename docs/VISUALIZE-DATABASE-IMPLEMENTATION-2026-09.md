# Visualize المرتبط بقاعدة البيانات — سجل التنفيذ

## القرار المعماري

يوجد مساران لا ينبغي خلطهما:

| المسار | الوظيفة | البيانات | النشر |
|---|---|---|---|
| `visualize/` | عرض عام، تجربة، توثيق، ومصادر عامة | JSON تجريبي معلّم، وإشارات طقس/خرائط عامة منفصلة | GitHub Pages |
| `apps/web/client/src/pages/LiveVisualize.tsx` | لوحة قرار تشغيلية | استعلامات مجمعة من جداول Urban‑Sense بعد المصادقة والصلاحية | تطبيق Urban‑Sense الكامل |

GitHub Pages لا يشغّل خادماً ولا قاعدة بيانات ولا جلسات OAuth؛ لذلك لا يجوز جعله واجهة التحليلات الخاصة أو إدخال أسرار إليه.

## ما تم تنفيذه

أضيف مسار `analytics.overview` إلى tRPC. يستقبل `municipalityId`، يتحقق من أن المستخدم مصادق وله عضوية فعالة أو دور مدير منصة، ثم يقرأ من قاعدة البيانات:

- إجمالي البلاغات.
- البلاغات المفتوحة.
- البلاغات المغلقة.
- البلاغات بانتظار التحقق.
- البلاغات الحرجة.
- متوسط ساعات الإغلاق للبلاغات المغلقة فقط.
- توزيع الحالات.
- توزيع البلاغات حسب التصنيف.
- ملخص دورة الحالة من سجل `report_status_history`.
- آخر البلاغات مع المرجع العام والعنوان والحالة والتصنيف ووقت التحديث.

لا يعيد المسار أسماء المواطنين أو أوصافهم أو مواقعهم التفصيلية أو الأدلة المرفوعة.

## ما لم يكتمل بعد

- نشر نسخة `apps/web` الحالية في بيئة Full‑Stack مرتبطة بقاعدة تشغيلية مملوكة ومهاجرة.
- إنشاء مستخدم بلدية ومجموعة عضوية حقيقية واختبار الصلاحية في بيئة قبول.
- توفير مراقبة وسجل أداء للاستعلامات عند زيادة البيانات.
- إضافة مؤشرات زمنية يومية/أسبوعية بعد توفر تاريخ كافٍ، بدلاً من استنتاج اتجاهات من snapshot صغير.
- عدم إضافة بيانات تجريبية إلى قاعدة الإنتاج لمجرد ملء الرسوم.

## تصحيح طريقة GitHub

القاعدة الجديدة:

1. التطبيقات الكاملة تعيش داخل `apps/*` ولكل تطبيق `package.json` وlockfile واختبارات وبنية نشر.
2. الملفات الثابتة في `visualize/` و`public-index/` لا تتظاهر بأنها backend.
3. كل Feature قاعدة بيانات يغيّر schema أو router أو UI أو test في commit واحد قابل للمراجعة.
4. GitHub Actions يفحص ويبني؛ لا يضع أسراراً ولا ينشر قاعدة بيانات تلقائياً.
5. التغييرات المتزامنة على `main` تُدمج بـ`fetch + rebase` مع حل التعارض، ولا يُستخدم force push.
6. أي نشر كامل يحتاج بيئة Full‑Stack منفصلة، وDATABASE_URL، وترحيلات، وOAuth، ونسخ احتياطي، وتحققاً بصرياً.
