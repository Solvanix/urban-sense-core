# خطة تشغيل المحتوى لمنصة SENSE

**الإصدار:** 1.0 — 2026-09-20  
**الحالة:** خطة تنفيذ قابلة للمراجعة، وليست إعلانًا عن إطلاق أو شراكة مكتملة.

## 1. القرار التشغيلي

تستخدم SENSE قواعد اختبار تطوير المحتوى بوصفها نظامًا تحريريًا عمليًا: افتتاح واضح، قصة مرتبطة بالمكان والناس، معلومة قابلة للتحقق، دعوة واحدة للفعل، وصياغة مختلفة لكل قناة. لا نضيف اسمًا أو رقمًا أو سعرًا أو حجزًا أو شراكة إلا إذا كان له مصدر أو مراجعة محلية واضحة.

يُحافظ النظام على الفصل التالي:

| الطبقة | الوظيفة |
|---|---|
| GitHub | البيانات المنظمة، المصادر، سجل التغييرات، المخططات، وقرارات المنتج |
| WordPress | المسودات والقصص والصفحات العامة بعد المراجعة البشرية |
| Facebook وInstagram | الاكتشاف، المجتمع، الفيديو القصير، وجمع الاهتمام |
| X | التحديثات السريعة، التحقق، والروابط المختصرة |
| LinkedIn | الشراكات، النتائج، النموذج التشغيلي، والتواصل المؤسسي |
| شركة الباصات | التشغيل الميداني للرحلات وفق عقد أو اتفاق واضح |

## 2. قالب كل مادة

لا تبدأ الكتابة قبل إنشاء بطاقة مادة تحتوي على:

- `id`: معرف ثابت.
- `type`: قصة مكان، خبر محلي، ملف وجهة، قصة منتج، قصة مشروع، أو تحديث تشغيل.
- `title`: عنوان واضح غير مبالغ.
- `hook`: افتتاحية قصيرة.
- `place`: المكان أو المسار.
- `question`: السؤال الذي تجيب عنه المادة.
- `human_detail`: تفصيل إنساني أو حسي له مصدر أو موافقة.
- `facts`: الوقائع المؤكدة.
- `unknowns`: ما لم يُتحقق منه بعد.
- `source`: رابط أو مقابلة أو وثيقة.
- `rights`: حالة حقوق النص والصورة والصوت.
- `access`: معلومات الوصول التي تمت مراجعتها.
- `next_action`: الفعل التالي الممكن.
- `cta`: دعوة واحدة فقط.
- `status`: `draft`, `needs_review`, `verified`, `published`, `archived`.
- `last_reviewed`: تاريخ آخر مراجعة.

## 3. سير GitHub

1. تُفتح Issue أو مسودة للمادة مع سؤال واضح.
2. تُضاف بطاقة المادة والمصادر وحقوق الوسائط.
3. تُكتب المسودة في فرع منفصل، لا مباشرة على `main`.
4. يراجع شخص آخر الادعاءات والخصوصية والوصول.
5. يُفتح Pull Request بعنوان يصف التغيير.
6. تُراجع الحقول المتصلة في `tourism/data/routes.json` إذا كانت المادة مرتبطة بمسار.
7. بعد القبول، يُدمج التغيير ويُسجل في `CHANGELOG.md`.
8. لا تُرفع أسرار أو كلمات مرور أو بيانات شخصية غير لازمة.

### أسماء الفروع وطلبات الدمج

- `content/story-<id>` للمادة الجديدة.
- `content/review-<id>` لتحديث مادة.
- `routes/update-<id>` لتغيير بطاقة مسار.
- `docs/wordpress-social-plan` للوثائق التشغيلية.

عنوان Pull Request المقترح:

> `content: add verified draft for <place or story id>`

## 4. سير WordPress

WordPress هو طبقة التحرير والنشر العام، وليس مصدرًا بديلًا للبيانات التشغيلية. تبدأ كل مادة كمسودة، ثم تمر بالمراحل الآتية:

1. **مسودة:** النص موجود، لكنه غير جاهز للعموم.
2. **مراجعة الوقائع:** مطابقة كل ادعاء بمصدره.
3. **مراجعة المكان والخصوصية:** التحقق من الإذن، التصوير، ومعلومات الوصول.
4. **مراجعة الوصول:** العناوين، النص البديل، التباين، لوحة المفاتيح، حجم الوسائط.
5. **مراجعة القناة:** عنوان ووصف وCTA مناسب للمنصة.
6. **نشر:** بعد موافقة بشرية واضحة.
7. **أرشفة وتحديث:** تسجيل تاريخ آخر مراجعة، وإيقاف أي معلومة منتهية.

### الصفحات ذات الأولوية

1. صفحة تعريف SENSE وحدودها.
2. صفحة المسارات التجريبية.
3. صفحة كل محطة أو قصة.
4. صفحة الكتالوج الرقمي.
5. صفحة «كيف نعرف حالة التجربة؟».
6. صفحة الشركاء والمساهمين دون ادعاء شراكة قبل وجود موافقة.
7. صفحة المصادر والحقوق.
8. صفحة الوصول والخصوصية.
9. صفحة طلب رحلة أو تجربة، بصيغة اهتمام إذا لم يوجد حجز حي.

### قاعدة الرحلة والباص

إذا أُضيفت تجربة مع شركة باصات، تُعرض بوصفها **رحلة أو Pilot قيد التحقق** إلى أن يثبت العقد والموعد والسعر والسعة والسياسة. لا نكتب «احجز الآن» أو «متاح» دون نظام تشغيل فعلي. تُستخدم صفحة WordPress لشرح القصة والمسار، بينما تعرض بطاقة GitHub حالة التشغيل والمصدر والدليل التالي المطلوب.

## 5. خطة القنوات الاجتماعية

### Facebook

الهدف: الوصول المحلي، القصص الأطول، المجتمع، الاستفسارات، والرحلات التجريبية.

- منشور قصة واحد أسبوعيًا.
- منشور عملي للمسار أو الفعالية أسبوعيًا.
- Stories في أيام الاختبار أو التحديث.
- CTA واحد: اقرأ، افتح المسار، سجّل اهتمامك، أو اسأل قبل الزيارة.
- لا تُترك الاستفسارات في Messenger فقط؛ تُسجل في جدول أو CRM تملكه SENSE.

### Instagram

الهدف: جعل المكان قابلًا للتخيل دون تحويله إلى صورة سياحية سطحية.

- Reel واحد أسبوعيًا من مادة موثقة أو مصرح بها.
- Carousel يشرح مسارًا أو محطة كل أسبوعين.
- Stories للأسئلة، الاقتراحات، وحالة التحقق.
- نص بديل ووصف واضح لكل مادة.
- لا تُصوّر الوجوه أو البيوت أو الأطفال دون موافقة مناسبة.

### X

الهدف: التحديثات القصيرة، مصادر التحقق، وتصحيح الالتباس.

- سلاسل قصيرة عند وجود موضوع يستحق السياق.
- رابط المصدر أو صفحة القصة.
- وسم الحالات: مسودة، قيد التحقق، مراجع، محدث.
- لا تُستخدم الصياغة العاجلة إلا عند وجود قيمة زمنية حقيقية.

### LinkedIn

الهدف: مخاطبة البلديات، المؤسسات، الممولين، شركات النقل، والشركاء التقنيين.

- منشور نتيجة أو قرار كل أسبوعين.
- دراسة حالة قصيرة بعد كل Pilot.
- شرح واضح لما هو مبني وما هو قيد التجربة.
- فصل قدرة SENSE التقنية عن الادعاء بوجود منتج سياحي تشغيلي.
- CTA مؤسسي: اطلب موجز الشراكة أو راجع خطة الـPilot.

## 6. مؤشرات القياس

لا تُقاس الحملة بالإعجابات وحدها. يُسجل لكل قناة:

| المرحلة | المؤشر |
|---|---|
| الوصول | الوصول، المشاهدات، مصدر الزيارة |
| الاهتمام | فتح صفحة القصة، مسح QR، تشغيل الصوت، وقت القراءة |
| النية | استفسار مؤهل، تسجيل اهتمام، طلب عرض |
| التشغيل | حضور الرحلة، اكتمال التجربة، ملاحظات الركاب |
| القيمة | حجز أو عقد، إيراد صافي، هامش المساهمة، شريك مستمر |
| الثقة | تصحيح معلومة، طلب إزالة، موافقة محفوظة، تاريخ تحديث واضح |

تُربط الروابط بوسوم UTM، ويكون مصدر الحقيقة للحجز أو الإيراد خارج Meta إذا لم يوجد تكامل موثوق.

## 7. جدول تنفيذ 30 يومًا

### الأيام 1–7: التأسيس

- اعتماد قالب المادة.
- إضافة مخطط البيانات.
- اختيار مسار واحد و5–10 محطات كحد أقصى.
- تجهيز سجل المصادر والحقوق.
- إعداد مسودة صفحة WordPress للمسار.
- إعداد قوالب منشورات القنوات الأربع.

### الأيام 8–14: الإنتاج

- كتابة خمس قصص قصيرة.
- مراجعة الوقائع والخصوصية.
- تجهيز صورة أو صوت مرخص لكل قصة عند الإمكان.
- إضافة البطاقات إلى GitHub بحالة `needs_review`.
- إعداد QR داخلي لا يُعلن قبل اختبار الرابط.

### الأيام 15–21: تجربة محدودة

- نشر قصة أو قصتين كمسودات WordPress للمراجعة.
- تنفيذ محتوى اجتماعي محدود.
- اختبار QR والهواتف والاتصال الضعيف.
- تنفيذ رحلة أو معاينة مع شركة الباصات فقط بعد الاتفاق التشغيلي.
- تسجيل الملاحظات دون ادعاء نجاح تجاري.

### الأيام 22–30: التقييم

- مراجعة فتح القصص والاستفسارات والرحلة.
- تحديث الحالات والروابط.
- كتابة تقرير Pilot مختصر.
- تقرير ما يستمر وما يتوقف.
- فتح Pull Request للنسخة التالية.

## 8. بوابة القرار

لا ننتقل إلى حجوزات أو دفع أو تكامل آلي إلا إذا تحققت الشروط التالية:

- مصدر واضح لكل ادعاء مركزي.
- موافقة للوسائط والأشخاص عند الحاجة.
- مسار قابل للوصف دون وعود غير مثبتة.
- شريك تشغيل معلوم، مثل شركة الباصات، بعقد أو عرض مكتوب.
- نموذج اهتمام أو حجز يمكن تتبعه.
- مؤشرات أولية تظهر قيمة فعلية لا مجرد وصول.
- خطة تراجع إذا تغير السعر أو المسار أو التوافر.

## 9. ما لن يُنفذ الآن

- نشر تلقائي من GitHub إلى WordPress.
- حجز أو دفع حي دون مالك تشغيلي وسياسة إلغاء.
- متجر عام غير مرتبط بالمسارات.
- إعلان شراكات أو اعتماد بلدي دون وثيقة.
- استخدام صور مولدة بوصفها توثيقًا ميدانيًا.
- نظام نقل متقدم لمسار ثابت قبل إثبات الحاجة.

## تعريف النجاح في المرحلة الأولى

النجاح ليس إطلاق أكبر عدد من الصفحات. النجاح هو امتلاك **مسار واحد موثق وقابل للمراجعة**، قصة منشورة بطريقة مسؤولة، تجربة رقمية يمكن فتحها من الهاتف، وشريك تشغيل أو جمهور حقيقي يعطي ملاحظات قابلة للاستخدام.
