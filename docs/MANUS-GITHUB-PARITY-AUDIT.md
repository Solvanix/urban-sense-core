# تدقيق تطابق Urban‑Sense بين Manus وGitHub

**تاريخ التحقق:** 16 أغسطس 2026

**النطاق:** مقارنة مشروع Manus الحي في `urban-sense-core-app` مع التطبيق البلدي المصدر في `apps/web` على فرع `main` من `Solvanix/urban-sense-core`.

## الخلاصة التنفيذية

لا توجد **ميزة تطبيقية أو ملف مصدر تشغيلي** في نسخة Manus الحية يحتاج إلى نقل جديد كي تصبح نسخة GitHub المركزية ممثلة لمنصة Urban‑Sense. المسارات العامة، صفحات البلاغات والعمليات، خادم tRPC/Express، مخطط Drizzle، الترحيلات، اختبارات الخادم، وتكوين البناء موجودة في `apps/web`.

الفروق الفعلية تنقسم إلى بيانات تشغيل Manus ومذكرات محلية، لا إلى كود مفقود. لذلك لا ينبغي نسخ المشروع الحي فوق GitHub أو نقل قاعدة البيانات أو الأسرار أو السجلات إليه. يبقى المستودع المركزي هو **مصدر الحقيقة للكود والتوثيق المنتجّي**، بينما تبقى Manus بيئة التشغيل والنشر الحالية لـUrban‑Sense.

> هذا التدقيق لا يدّعي أن GitHub بديل تلقائي لخدمات النشر أو قاعدة البيانات الحية في Manus؛ إنه يثبت أن **مصدر التطبيق** متزامن وظيفيًا، لا أن إعدادات الإنتاج وبياناته نُسخت.

## سجل التحقق والجودة

| التحقق | النتيجة | الدليل |
|---|---|---|
| فحص الأنواع في `apps/web` | ناجح | `pnpm check` اكتمل من دون أخطاء. |
| اختبارات Urban‑Sense | ناجحة | `pnpm test`: خمس ملفات اختبار و19 اختبارًا ناجحًا. |
| البناء الإنتاجي | ناجح | `pnpm build` اكتمل وبنى Vite وحزمة خادم Node. ظهر تنبيه حجم حزمة فقط، لا فشل. |
| بوابة جودة GitHub | ناجحة | التشغيل `31921088122` على الالتزام `012a7d8` أكمل فحص الأنواع والاختبارات والبناء بنجاح. |
| بوابة خط الأساس النهائية | ناجحة | التشغيل `31921153204` على الالتزام `93f266e` اجتاز فحص المسافات وملفات البيئة وبيانات الخط الأساس. |

أظهر أول تنفيذ لبوابة خط الأساس مساحة زائدة في رأس التقرير. أزيلت في التزام مستقل، ثم أعيد الفحص بنجاح. لا يمثل ذلك عيبًا في التطبيق أو اختلافًا بين Manus وGitHub، لكنه يثبت أن فحص النظافة يعمل كما ينبغي.

## نطاق المطابقة ونتيجتها

| المجال | النتيجة | الملاحظة |
|---|---|---|
| واجهة المواطن والعمليات | متطابق وظيفيًا | المسارات والصفحات العامة والخاصة موجودة في التطبيقين. |
| خادم التطبيق وواجهات tRPC | متطابق وظيفيًا | لا توجد ملفات خادم أو إجراءات بلدية حية غير موجودة في `apps/web`. |
| مخطط Drizzle والترحيلات | متطابق | لا فرق في `drizzle.config.ts` أو حزمة التطبيق؛ لا تُنسخ بيانات قاعدة التشغيل. |
| أوامر البناء والحزم | متطابقة | `package.json` متطابق بين النسخة الحية و`apps/web`. |
| الاختبارات | GitHub أوسع قليلًا | إعداد GitHub يضم اختبارات الخادم واختبارات العميل؛ إعداد Manus يقتصر على اختبارات الخادم. هذا تحسين في التغطية وليس فجوة. |
| الصفحات العامة | لا فرق وظيفي | الاختلافات في `App.tsx` و`PublicHeader.tsx` و`PublicFooter.tsx` و`publicSite.test.ts` هي ترتيب استيراد أو صياغة دوال فقط. |
| صفحات التعريف العامة | فرق مسافات فقط | `Home.tsx` و`HowItWorks.tsx` و`ForMunicipalities.tsx` متماثلة بعد تجاهل المسافات. |

## ما لا يُنقل إلى GitHub

| الصنف | أمثلة مفحوصة | قرار المزامنة | السبب |
|---|---|---|---|
| إعدادات Manus الداخلية | `.project-config.json` | لا يُنقل | إعداد تشغيل خاص بالمنصة وليس مصدر تطبيق. |
| سجلات التشغيل والجلسات | `.manus-logs/*` | لا يُنقل | قد تحتوي سياق تشغيل أو تشخيصًا غير مناسب للمستودع؛ لا تمثل ميزة منتج. |
| بيانات الإصدار المنشور | `client/public/__manus__/version.json` | لا يُنقل يدويًا | فرق الطابع الزمني ومعرّف الإصدار ناتج عن النشر فقط. |
| متغيرات البيئة والأسرار | لا توجد ملفات `.env` ملتزمة؛ يوجد `.env.example` فقط | لا يُنقل | يمنع تعريض مفاتيح الوصول أو روابط قواعد البيانات أو بيانات الجلسات. |
| بيانات قاعدة التشغيل | سجلات المستخدمين والبلاغات والأدلة والتدقيق | لا يُنقل | يجب أن تبقى في قاعدة البيانات والتخزين المخصصين؛ ليست ملفات مصدر. |

## المذكرات المحلية غير المزامنة

توجد في جذر مشروع Manus مذكرات محلية تخص حملات LinkedIn، مراجعات روابط وصور مرجعية، حالة تجربة التشغيل، استرداد الحساب، ومراجعات أرشيفية. هذه ليست مكونات منصة Urban‑Sense، ولا ينبغي نقلها جماعيًا إلى المصدر المركزي. بعض المعرفة القابلة لإعادة الاستخدام قد نُقلت بالفعل إلى وثائق المنتج والبحث داخل `docs/`.

أي نقل لاحق يجب أن يكون **انتقائيًا** إلى `docs/` بعد مراجعة المحتوى، مع استبعاد سجلات النشر، بيانات الحسابات، وحالات التواصل الخاصة. لا توجد حاجة تقنية إلى هذه المذكرات لكي يُبنى أو يُختبر التطبيق.

## تسلسل العمل الآمن من الآن

أولًا، تُنفّذ التحسينات الجديدة في `apps/web` داخل المستودع المركزي، ثم تُراجع عبر فحص الأنواع والاختبارات والبناء وتُدفع إلى `main`. بعد ذلك فقط تُنقل التغييرات المقصودة إلى مشروع Manus الحي وتُراجع بصريًا قبل حفظ نقطة إصدار. بهذه الطريقة لا يصبح مشروع Manus مصدر تعديلات غير موثقة.

ثانيًا، يظل العمل السياحي في `apps/sense-experience` مستقلًا عن Urban‑Sense: هوية مراجع مستقلة، قاعدة بيانات مستقلة، أسرار مستقلة، ونشر مستقل. لا تنقل جلسة Manus OAuth أو قاعدة بيانات Urban‑Sense إلى SENSE Experience.

ثالثًا، التحسين التالي ذي الأولوية لUrban‑Sense هو **نظام بلاطات عربي متنوع للصفحات العامة**. يُبنى أولًا في GitHub مع عمق تحريري هادئ ووضوح عالٍ، من دون نسخ التصميم المؤرشف، ثم يُزامن إلى Manus ويُتحقق منه على الشاشات الكبيرة والهاتف.

## قرار التدقيق

لا توجد عملية ترحيل كود معلّقة من Manus إلى GitHub. بدلاً من ذلك، تعتمد الأعمال التالية على GitHub بوصفه نقطة البداية: تطوير نظام البلاطات، استكمال هوية ومفاتيح مراجعي SENSE Experience، ثم تهيئة قاعدة بيانات سياحية مستقلة بعد استيفاء بوابة قبول البيانات الحقيقية. يظل حذف المستودع الخاطئ `Solvanix/sense-experience-platform` قرارًا منفصلًا يحتاج موافقة صريحة من المالك.
