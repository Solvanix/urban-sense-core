# توصية تسليم لمشروع Manus القادم — تصحيح بروفايل فلسطين تكنوبارك

## الهدف الإلزامي
يوجد بروفايل مؤسسي عام واحد فقط لتكنوبارك. يجب تصحيح المنشور القديم نفسه، وعدم إنشاء منشور جديد أو رابط جديد إلا إذا طلب المستخدم ذلك صراحة.

## الرابط الأساسي
- الموقع: `sense133.wordpress.com`
- المنشور المعتمد: رقم `146`
- الرابط الثابت: `https://sense133.wordpress.com/2026/09/27/palestine-techno-park-profile/`
- الرابط المختصر الذي شاركه المستخدم مع الأستاذ: `https://wp.me/phpKVO-2m`
- الحالة المطلوبة: `publish`

## النسخ غير المعتمدة
- المنشور 167 كان نسخة موسعة مكررة؛ يبقى `draft` قابلًا للاسترجاع ولا يُنشر.
- المنشور 89 نسخة قديمة في المهملات؛ لا يُعاد نشره.
- أي مسودة أخرى لا تُنشر تلقائيًا.

## بروتوكول العمل قبل أي تعديل
1. قراءة سجل المحادثات والتفريغات والملفات السابقة كاملًا.
2. قراءة المنشور 146 كاملًا وحفظ نسخة محلية مؤرخة.
3. فحص WordPress revisions أو Activity Log إن كانت متاحة.
4. مقارنة 146 مع 167 والنسخ القديمة، واستخراج الإضافات فقط.
5. عدم تغيير slug أو الرابط أو إنشاء منشور بديل.
6. عدم وضع التفريغات أو أسئلة المقابلات أو الملاحظات الداخلية في النص العام.
7. استخدام الاقتباس المباشر فقط مع متحدث معروف ونص موثق وحقوق نشر واضحة.
8. نسب كل رقم وتاريخ وبرنامج إلى مصدره؛ وعدم تحويل إعلان المؤسسة إلى دليل مستقل على الأثر.
9. التمييز بين الواقع المنجز، والوصف المؤسسي، والخطة المستقبلية، والسيناريو التحريري.
10. بعد التحديث، فحص الرابط 2m علنًا، والعنوان، والمقدمة، والخاتمة، والمصادر، والصور، والروابط، وغياب الملاحظات الداخلية.

## قائمة تصحيح خاصة بالنسخة الحالية
- إزالة أي عبارة تخاطب Manus أو الأستاذ أو مشروعًا داخليًا.
- إزالة عبارة تفيد بأن التفريغات محفوظة في أرشيف داخلي من نهاية المقال العام؛ التفريغات مادة إنتاج داخلية وليست مصدرًا منشورًا.
- عدم تقديم بريد Udacity الشخصي بوصفه مصدرًا عامًا؛ يذكر فقط إذا أُرفق بإذن أو يُحفظ في الأرشيف.
- تصحيح رابط Creative Cluster Campus إلى الرابط الرسمي الصحيح.
- إضافة مصدر SPARK الرسمي لخبر Launchpad، مع إبقاء نتائج التوظيف غير مثبتة ما لم توجد بيانات لاحقة.
- وسم الصور الاصطناعية بوضوح بأنها تصور بصري، وعدم تقديمها كتوثيق للمبنى.
- إبقاء الأسئلة الصحفية العامة بصياغة للقارئ، لا بصيغة «ما الذي نحتاج إلى التحقق منه؟».

## مآل التفريغات
تستخدم التفريغات لاستخراج الزوايا، والأسماء، والتواريخ، والقصص، والسبق المحتمل، وأسئلة المقابلات. لا تُنسخ كاملة إلى البروفايل. كل معلومة مستخرجة منها تحتاج إلى تحديد المتحدث والمصدر والتاريخ ودرجة الثقة قبل النشر.

## بنية المحتوى الصحيحة
1. بروفايل مؤسسي واحد ثابت.
2. أخبار مستقلة للأحداث الراهنة.
3. قصص أو مقابلات مستقلة للخريجين والشركات والمختبرات.
4. أرشيف داخلي للتفريغات والأدلة وأسئلة التحقق.
5. روابط متبادلة بين البروفايل والمواد المستقلة بدل تكرار كل شيء في منشور واحد.

## مراجعة تاريخ التغييرات
إذا لم توفر WordPress revisions أو Activity Log كل التاريخ، لا يُخترع تاريخ. تُراجع سجلات محادثات Manus، والروابط، وملفات handoff، والنسخ المحلية، مع تسجيل ما هو مؤكد وما بقي غير قابل للإثبات.

## بوابة الجودة قبل التسليم
لا يُسلّم العمل إلا بعد تحقق مستقل من:
- بقاء الرابط 2m نفسه.
- وجود منشور واحد عام فقط.
- سلامة العنوان والمقدمة والخاتمة.
- عدم وجود نص داخلي أو تعليمات تشغيل.
- صحة الروابط والأرقام والتواريخ.
- توضيح مصادر كل claim.
- بقاء النسخ السابقة قابلة للاسترجاع دون ظهورها للعامة.
