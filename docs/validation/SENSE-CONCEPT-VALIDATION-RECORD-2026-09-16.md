# سجل تحقق مفهوم SENSE — 16 سبتمبر 2026

## القرار التنفيذي

لا نعامل SENSE بوصفها «منصة سياحية ذكية» مكتملة. القرار الحالي هو **تثبيت نواة أصغر قابلة للاختبار**: غرفة تحرير مكانية تبدأ من العيزرية وضواحي القدس، وتحوّل ملاحظة ميدانية إلى مادة موثقة قابلة للنشر، ثم تربطها بخريطة أو مسار أو مؤشر حركة عند توفر الدليل.

تبقى طبقة البيانات المرورية وواجهات التشغيل **تجارب تفسيرية** إلى أن تُختبر بمشاهدات ميدانية ومصادر تشغيلية واضحة. لا يجوز تحويل القراءة التجريبية أو النموذج البصري إلى وعد عن الازدحام أو عدد المواقف أو أثر اقتصادي.

هذا السجل يطبق مبادئ ملف **UrbanUp V2 — Technical Feasibility & Concept Validation** المرفق بالمشروع. الملف يعرّف قابلية التنفيذ بأنها قدرة الحل على أن يعمل ويُشغّل ويُصان ويُبرّر تحت القيود الواقعية، لا مجرد القدرة على برمجته.

## حالة الأدلة

| المستوى | معنى المستوى | حالة SENSE الحالية |
|---|---|---|
| 0 | اعتقاد الفريق | موجود في الأفكار والفرضيات غير المختبرة |
| 1 | مقابلة أو اهتمام معلن | متاح جزئيًا من نقاشات الفريق وأصحاب القصص |
| 2 | اختبار مستخدم منظم أو قياس ميداني | مطلوب لمسارات الحركة وصياغة الأخبار الخدمية |
| 3 | نموذج مستخدم داخل سير عمل | متحقق بصريًا في لوحة التحرير، وليس سير عمل بلديًا |
| 4 | بيانات تجربة واقعية | غير متحقق بعد |
| 5 | تجربة مدفوعة أو متعاقد عليها | غير منطبق حاليًا |

**قاعدة النشر:** لا نرفع مستوى الدليل بالصياغة البلاغية. عبارة «أبدى اهتمامًا» لا تصبح «اعتمد الحل»، وواجهة تعمل على جهاز الفريق لا تصبح «اختبارًا ميدانيًا».

## حالة الاستخدام الأساسية

**المستخدم:** مراسل أو منتج محتوى يعمل في العيزرية وضواحي القدس.

**المهمة:** التقاط قصة أو واقعة مرتبطة بمكان، تثبيت المصدر والموقع والزمن، اختيار الشكل الصحفي المناسب، ثم نشر مادة لا تخلط الخبر بالرأي أو العلاقات العامة.

**الفشل القابل للقياس:** نشر مادة بمكان غامض، أو مصدر غير قابل للمراجعة، أو ادعاء مروري لا يمكن إسناده، أو قصة إنسانية بلا موافقة أو حقوق صورة واضحة.

**القيمة:** مادة أكثر دقة وقابلية للمراجعة، تساعد الجمهور على فهم المكان بدل استهلاكه كصورة دعائية.

## حدود المفهوم

### داخل النطاق الآن

- بطاقة تغطية عربية RTL تربط الفكرة بالمكان والمصدر والدليل الأولي.
- تصنيف تحريري واضح: خبر، قصة، تقرير، تحقيق، وبورتريه.
- فصل «ما نعرفه» عن «ما نفترضه» وعن «ما يحتاج تحققًا».
- تحويل المادة إلى News Bar أو SMS أو قصة أو تقرير أو إنفوغراف بحسب السؤال والجمهور.
- ربط المادة المنشورة ببوابة SENSE Routes وواجهة التصور ومصدر GitHub.
- سجل قرارات واختبارات داخل المستودع.

### خارج النطاق حتى يثبت الدليل

- اعتبار SENSE نظامًا بلديًا أو مصدرًا رسميًا للبيانات.
- إصدار تنبيهات مرورية حية أو توصيات سلامة دون مصدر تشغيلي وزمن رصد.
- الادعاء بوجود أثر اقتصادي أو زيادة زوار اعتمادًا على واجهة أو قصة واحدة.
- تشغيل مدفوعات أو حسابات مزودين أو تكاملات حكومية غير موثقة.
- استخدام الذكاء الاصطناعي بدل المراسل أو المحرر أو صاحب القصة.

## مسار الفشل قبل مسار النجاح

- عند انقطاع الاتصال: تحفظ البطاقة محليًا أو يدويًا، ولا تُنشر تلقائيًا.
- عند ضعف المصدر: تبقى المادة مسودة مع وسم «يحتاج تحققًا».
- عند تعارض مصدرين: يظهر التعارض في سجل التحرير بدل اختيار الرقم الأكثر جاذبية.
- عند غياب API أو بيانات بلدية: نستخدم رصدًا يدويًا موثقًا أو نوقف الادعاء التشغيلي.
- عند غموض الموافقة أو حقوق الصورة: لا تنشر الصورة القابلة للتعرف حتى يحسم المحرر الحالة.
- عند فشل الواجهة: تبقى الوثيقة والنموذج اليدوي قادرين على حمل العمل؛ لا تعتمد العملية على الشاشة وحدها.

## نموذج التجربة الأولى

نختبر سيرًا واحدًا من البداية إلى النهاية: **خبر خدمي مكاني عن الحركة بين العيزرية والقدس**.

1. يلتقط المراسل الملاحظة مع المكان والزمن.
2. يسجل المصدر الأولي ويحدد ما لم يُتحقق منه.
3. يجمع قياسًا يدويًا أو رابطًا رسميًا قابلًا للمراجعة.
4. يصوغ خبرًا قصيرًا بلا فاصلة أو نقطة في العنوان، ويضع المكان في آخر الجملة عند الحاجة.
5. يراجع المحرر المصدر واللغة وحدود الادعاء.
6. ينشر نسخة WordPress ويربطها بواجهة SENSE أو GitHub دون تقديم النموذج كبيانات حية.
7. يسجل بعد النشر ما إذا احتاج الخبر تحديثًا أو تصحيحًا.

**قرار التجربة:** نوسع الوظيفة إذا أمكن إغلاق خمس مواد متتالية دون مصدر مختلق أو مكان غامض أو خلط بين «تجريبي» و«موثق». نعيد التصميم إذا فشل الفريق في ثلاث حالات أو أكثر.
