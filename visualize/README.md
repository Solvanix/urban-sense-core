# SENSE Visualize

واجهة تصور ديناميكي خفيفة تعمل من GitHub Pages دون خادم، وتقرأ عقد بيانات JSON قابلة للاستبدال. الهدف هو تحويل مؤشرات SENSE/TIBYAN إلى شاشة تشغيل يمكن أن تتطور من نموذج أولي إلى لوحة بلدية موثقة.

## التشغيل

افتح `visualize/index.html` عبر GitHub Pages. التطبيق يقرأ افتراضياً من `visualize/data/dashboard.json`، ويعيد رسم المؤشرات والرسوم عند الضغط على «تحديث الآن» أو وفق فترة المزامنة التي يحددها المستخدم.

يمكن استخدام مصدر عام بديل بإضافة معامل URL:

```text
https://solvanix.github.io/urban-sense-core/visualize/?data=https%3A%2F%2Fexample.org%2Fdashboard.json
```

يجب أن يعيد المصدر الخارجي JSON صالحاً وأن يسمح بالقراءة من المتصفح عبر CORS. لا تُضع مفاتيح سرية أو رموز وصول داخل رابط المصدر أو ملفات GitHub Pages.

## مسارا العرض

تحتوي المساحة الآن على مسارين مقصودين لجمهورين مختلفين. لوحة `index.html` هي لوحة التشغيل التي يقرأها المستثمر أو البلدية لمتابعة المؤشرات، البلاغات، الأولويات، الشبكة، والحوكمة. أما `experience.html` فهي Experience Visualizer؛ خريطة رحلة تفاعلية للزائر والمبدع والمستثمر والبلدية، وتعرض الوحدات المعيارية: القصص، المسارات، الواقع المعزز، التجارب، الفرص الموسمية، الفعاليات، المرآة البلدية، والمهارات التطبيقية.

يستخدم المسار الثاني عقد بيانات منفصلاً في `data/experience.json` حتى يمكن تعديل سرد الرحلة والوحدات دون خلطه مع أرقام التشغيل. الواجهة لا تعرض صوراً مولدة أو صوراً مرجعية كأنها أصول منشورة؛ الرسوم الحالية مبنية برمجياً وبصرياً لتبقى قابلة للاستبدال بمصادر مرخصة عند تثبيت الهوية البصرية النهائية.

## التعديل والتصدير

توجد ثلاثة مسارات آمنة للتعديل:

| المسار | النتيجة |
|---|---|
| تحرير JSON من داخل الصفحة | يحفظ نسخة محلية في متصفح المستخدم ويعيد الرسم فوراً. |
| تعديل `data/dashboard.json` في المستودع | يغير المصدر العام بعد تنفيذ commit وتشغيل نشر GitHub Pages. |
| تمرير رابط `?data=` | يبدل المصدر في جلسة العرض، بشرط أن يكون JSON عاماً ويدعم CORS. |

يمكن طباعة الصفحة إلى PDF من المتصفح، كما يمكن تنزيل البيانات الحالية بصيغة JSON. لا يحاول التطبيق الكتابة مباشرة إلى GitHub من المتصفح، لأن ذلك يتطلب رمز وصول سرياً ولا ينبغي تضمينه في واجهة عامة.

## عقد بيانات Experience Visualizer

ملف `data/experience.json` يتضمن `audiences` لتبديل الوعد والمسار بحسب الجمهور، و`modules` لتصفية الوحدات، و`validation` لتحويل منهجية التحقق قبل البناء إلى واجهة، و`governance` لقواعد النشر. تغيير هذا الملف يعيد بناء تجربة الزائر عند التحديث.

## الانتقال من النموذج إلى بيانات موثقة

لا يكفي تغيير الأرقام. يجب أن يرافق كل مؤشر سجل تعريف يتضمن الاسم، التعريف، الصيغة، المصدر، المالك، تواتر التحديث، فترة القياس، ودرجة الثقة. في مرحلة البلديات، يُفضّل توفير تصدير مجمع ومجهّل من نظام البلاغات أو الاستبيانات، ثم نشر نسخة JSON للقراءة فقط عبر خدمة موثوقة أو مسار نشر آلي.

## ما الذي أُخذ من المواد المرفقة؟

يعكس التصور فجوة «الطبقة التشغيلية» في العيزرية: تحويل المحتوى إلى قصة، ثم مكان، ثم حدث أو مسار، ثم خدمة أو تجربة، ثم متابعة وقياس. كما يترجم دورة البلاغ البلدية إلى: استقبال، تصنيف، أولوية، إحالة، SLA، إغلاق، تقييم. ويستوعب نموذج شبكة المبدعين والوكالات، وفكرة SENSE AI Operating System المستلهمة من: Identity، Projects، Skills، Workflows، Artifacts، Verification. وتحوّل مسارات Maharat Spark إلى مخرجات داخل المنتج، بينما تظهر منهجية Foras كحلقة تحقق قبل بناء MVP: اكتشاف العميل، اختبار المشكلة، نموذج القيمة، ثم خارطة الطريق.

## الحالة الحالية

القيم الموجودة في `dashboard.json` موسومة بوضوح كبيانات أولية/تجريبية وليست نتائج ميدانية. يجب عدم استخدامها لإثبات أثر أو دخل أو وظائف قبل استبدالها بمصدر موثق وموافَق عليه.
