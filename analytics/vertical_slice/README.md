# أول Vertical Slice — بلاغات الوصول والتنقل

## النطاق

هذه الشريحة تقيس دورة بلاغ حضري واحدة من الإنشاء إلى الإقرار والإحالة والإغلاق والتقييم. النطاق محدود عمدًا إلى 112 بلاغًا اصطناعيًا موزعة على أربعة نطاقات مكانية خلال 1–14 أيلول 2026، حتى يمكن اختبار السلسلة كاملة قبل إدخال بيانات بلدية معتمدة.

## السلسلة

```text
seed/reports.csv
  ↓
SQLite runtime/sense_vertical_slice.sqlite
  ↓
analyze.py
  ↓
visualize/data/dashboard.json
  ↓
visualize/index.html
```

## مصدر البيانات وحقيقتها

`seed/reports.csv` هو **Fixture اصطناعي حتمي**، وليس تصديرًا ميدانيًا. كل سجل يحمل `source_ref`، والمعرّفات اصطناعية، ولا توجد بيانات شخصية. النمط الاصطناعي مقصود لاختبار ظهور منطقة تتجاوز عتبة الإغلاق بعد اليوم السابع؛ لا يجوز تفسيره كواقعة عن العيزرية.

## التشغيل

من جذر المستودع:

```bash
python3 analytics/vertical_slice/analyze.py
python3 -m unittest analytics/vertical_slice/test_analyze.py -v
```

يشغّل السكربت قاعدة SQLite محلية ويعيد توليد `visualize/data/dashboard.json`. قاعدة SQLite مستبعدة من Git لأنها مخرج تشغيل، بينما يبقى Fixture وJSON الناتج قابلين للمراجعة.

## التحليلات الحالية

يحسب المحرك:

- الوسيط حتى إقرار الاستلام.
- الوسيط حتى الإحالة.
- الوسيط حتى الإغلاق.
- معدل إعادة الفتح.
- متوسط التقييم.
- اتجاهًا يوميًا للوسيط حتى الإغلاق.
- مقارنة حسب المنطقة.
- توزيع البلاغات حسب الفئة.
- تنبيهًا عند تجاوز وسيط الإغلاق 24 ساعة.

## معيار الانتقال إلى بيانات حقيقية

قبل اعتماد الشريحة تشغيليًا، يجب استبدال Fixture بتصدير معتمد يحدد مالك البيانات، تعريف الحقول، فترة القياس، سياسة الإخفاء، وتواتر التحديث. عندها يظل المحرك نفسه قابلًا لإعادة الاستخدام، لكن يجب تغيير `data_status` وإرفاق سجل مصدر وموافقة.
