# SENSE Experience

## المهمة

خدمة مستقلة لمزودي التجارب والخدمات. يبدأ المزود بطلب اهتمام، يستلم مرجعًا ومفتاح متابعة، ثم يتلقى قرارًا مسببًا من مراجع مخوّل. الدعوة إلى ملف مزود أو النشر العام تأتيان في مراحل لاحقة وبموافقات منفصلة.

| الميزة | المصدر التنفيذي | تحقق القبول |
|---|---|---|
| طلب اهتمام ومتابعة خاصة | [`server/providerInterestService.ts`](../../apps/sense-experience/server/providerInterestService.ts) | يصدر مرجع ومفتاح مرة واحدة، ويخزن المفتاح مجزأً فقط. |
| قائمة مراجعة وقرار مسبب | [`server/router.ts`](../../apps/sense-experience/server/router.ts) | يكتب مراجع ذو دور مستقل قرارًا بسبب إلزامي. |
| عزل البيانات | [`drizzle/schema.ts`](../../apps/sense-experience/drizzle/schema.ts) | جداول `sx_*` وقاعدة MySQL مستقلة عن Urban‑Sense. |
| تشغيل مستقل | [`compose.yaml`](../../apps/sense-experience/compose.yaml) | واجهة وخدمة وقاعدة MySQL وترحيلات عبر أمر واحد. |
| حالة تشغيل | `GET /healthz` | يعرض وضع الخدمة ويفصل الواجهة المتاحة عن قبول بيانات المزودين. |

## تشغيل الخدمة

```bash
cd apps/sense-experience
bash ops/bootstrap-server.sh
```

يخدم الخادم الواجهة وAPI من أصل واحد. تبقى API الخاصة ببيانات المزودين مغلقة حتى تكتمل قاعدة MySQL المستقلة، موافقة فتح البيانات، OIDC، وهوية مراجع مفعّلة. خطوات الإعداد موجودة في [`ops/DEPLOYMENT.md`](../../apps/sense-experience/ops/DEPLOYMENT.md).

## الشريحة التالية

فتح مجموعة دعوات حقيقية صغيرة بعد اعتماد سياسة البيانات ومالك المراجعة. الاستبانة السياحية تغذي حقول الجاهزية والدليل ومسار التمكين؛ لا تدخل إلى الواجهة كقائمة أسئلة طويلة.
