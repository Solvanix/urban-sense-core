# تشغيل Urban‑Sense خارج Manus

هذه الحزمة تجعل المستودع المصدر الوحيد للكود وإعداد التشغيل غير السري. لا تحتوي على قاعدة بيانات حقيقية أو كلمات مرور أو ملفات مواطنين.

## ما يلزم على الخادم

يحتاج الخادم إلى Docker Engine وDocker Compose Plugin، وإلى وصول المطور المخوّل إلى المستودع الخاص. يلزم كذلك ملف `.env.runtime` محلي لم يُرفع إلى Git.

## إقلاع عرض محلي جديد

انسخ المثال ثم غيّر كل القيم البديلة إلى قيم فريدة:

```bash
cp .env.runtime.example .env.runtime
```

بعد ذلك شغّل:

```bash
bash ops/bootstrap-server.sh
```

ينشئ هذا المسار قاعدة MySQL فارغة محلية، ويطبّق مخطط Drizzle من `drizzle/schema.ts`، ثم يشغّل التطبيق. هذا الإقلاع مخصص لقاعدة عرض جديدة فقط. لا تشغّل `db:bootstrap` على قاعدة إنتاج تحتوي بيانات، لأن مزامنة المخطط تحتاج مراجعة وترحيلات معتمدة ونسخة احتياطية.

## اختبار الصحة

بعد الإقلاع، يجيب التطبيق عن:

```text
http://localhost:${APP_PORT}/healthz
```

ويكون الرد الناجح `{"status":"ok"}`.

## الإنتاج المستقل

يستخدم الإنتاج الحاوية نفسها، لكن لا يستخدم قاعدة البيانات المحلية داخل `compose.yaml`. بدلاً من ذلك:

1. أنشئ MySQL مُدارًا باسم الجهة وخزّن نسخة احتياطية قبل أي ترحيل.
2. عيّن `APP_BASE_URL` إلى عنوان HTTPS النهائي للتطبيق، وضع رابط قاعدة الإنتاج في بيئة الخادم، ثم طبّق ترحيلات مراجعة يدويًا.
3. اضبط `AUTH_MODE=oidc`، ثم زوّد `OIDC_ISSUER_URL` و`OIDC_CLIENT_ID` و`OIDC_CLIENT_SECRET` من مزود هوية تملكه الجهة قبل إتاحة تسجيل الدخول الخارجي. يبقى خيار `AUTH_MODE=manus` متاحًا للتوافق مع معاينة التطوير فقط.
4. اربط الدومين وTLS والتخزين المستقل في حساب الجهة.
5. اجعل النشر يأخذ إصدارًا معتمدًا من `main` بعد نجاح الاختبارات.

## حدود الحزمة الحالية

الحاويات تجعل التطبيق وقاعدة العرض قابلين للنقل. لكنها لا تنقل ملكية الدومين، ولا تنشئ مزود هوية، ولا تخلق حساب تخزين أو قاعدة إنتاج تلقائيًا. تلك قيم وخدمات تشغيلية يجب أن تُنشأ باسم الجهة وتُحقن في الخادم خارج Git.
