# مقارنة نسخ Pizza hot

| الحل | ما هو | ما يعمل الآن | الاعتماد | ما لم يُنفذ |
|---|---|---|---|---|
| Stunning | نسخة مولدة داخل منصة Stunning، وبها واجهة React وملفات Convex وAgent | معاينة داخل المنصة، صفحات Home/Menu/Cart/Checkout/Admin/Assistant، schema وseed وملفات assistant | يعتمد على بيئة Stunning وConvex وإعدادات `.env.local` داخل المنصة | لم يُثبت تصديره إلى GitHub في هذه الجلسة، ولا يجوز نقل أسراره |
| Manus | نسخة وسيطة محفوظة محلياً داخل مساحة Manus | إعادة بناء مستقلة للواجهة والكتالوج والسلة والمساعد النصي، بلا أسرار | لا تعتمد على Stunning؛ تحتاج خادم ملفات فقط | لا توجد قاعدة بيانات أو دفع أو WhatsApp أو توصيل فعلي |
| GitHub | النسخة التي ستُحفظ في `apps/pizza-hot/` داخل `urban-sense-core` | نفس نسخة Manus بعد الفحص والـcommit | GitHub Pages للواجهة الثابتة؛ Backend خارجي عند الإنتاج | لم تُرفع هذه النسخة حتى ينجح الفحص النهائي والـcommit |

## ما أخذناه من متجر SENSE

أُخذت أسماء المنتجات والأسعار التي ظهرت في ملف مزود Pizza hot، مع حفظ Provider ID 10 والرابط المرجعي. المنتجات بلا سعر مؤكد بقيت غير قابلة للطلب حتى يراجعها المزود.

## ما أخذناه من فكرة Agent

استُخدم السلوك العام الظاهر في العرض: مساعد يجيب من بيانات النشاط، يقرأ الكتالوج، يوجّه الأسئلة غير المعروفة للمراجعة البشرية، ولا يعتمد الطلب تلقائياً. لم تُنسخ شيفرة Stunning الداخلية أو أسرارها.

## قاعدة النقل

لا يجوز نقل `.env.local` أو `.env.local.ready` أو `CONVEX_DEPLOY_KEY` أو أي token إلى Manus أو GitHub. هذه النسخة تستخدم `catalog.json` وواجهة ثابتة حتى يكون الفرق واضحاً وقابلاً للفحص.
